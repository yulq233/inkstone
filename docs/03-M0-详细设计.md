## 1. 全局约定

### 1.1 命名与编码

| 项 | 约定 |
|---|---|
| 文件编码 | 一律 UTF-8（无 BOM），显式指定，**绝不依赖系统默认编码** |
| 换行 | 落盘统一 `\n`（LF） |
| 缩进 | TS 2 空格；Python 4 空格；JSON 2 空格 |
| 标识符 | 模块/变量 `snake_case`(py) / `camelCase`(ts)；类型 `PascalCase` |
| ID 格式 | work: `w_` + uuid4 hex 前 12 位；chapter: `ch_` + uuid4 hex 前 12 位 |
| 时间 | 一律 ISO 8601 带时区（`2026-09-18T16:49:19+08:00`），落盘用本地时区 |

### 1.2 错误与日志

**统一错误信封**（HTTP body）：

```json
{
  "error": {
    "code": "EXTERNAL_MODIFIED",
    "message": "文件已被外部修改",
    "detail": { "...": "code 相关载荷" },
    "traceId": "01J8X..."
  }
}
```

**错误码全集**（M0）：

| code | HTTP | 触发条件 | 前端行为 |
|---|---|---|---|
| `INVALID_PARAM` | 400 | 参数校验失败 | 提示字段 |
| `UNAUTHORIZED` | 401 | token 缺失或错误 | 视为致命，提示重启应用 |
| `WORK_NOT_FOUND` | 404 | workId 不存在或目录已删 | 回作品列表 |
| `CHAPTER_NOT_FOUND` | 404 | chapterId 不存在 | 刷新章节列表 |
| `WORK_EXISTS` | 409 | 目标目录已存在且非空 | 提示换目录 |
| `EXTERNAL_MODIFIED` | 409 | baseHash 与磁盘不一致 | 弹三选一对话框 |
| `WRITE_FAILED` | 500 | 落盘失败（含重试耗尽） | 强提示，禁止静默继续编辑 |
| `READ_FAILED` | 500 | 读取失败（权限/编码） | 提示并允许重试 |
| `INTERNAL` | 500 | 未预期异常 | 提示 + 输出 traceId |

**日志规范**：结构化 JSON 行，字段 `ts / level / logger / msg / traceId / extra`。
日志目录：`<userData>/logs/sidecar-YYYY-MM-DD.log`，保留 7 天。
**强制脱敏**：写入日志前过滤 `token` 字段与 `X-Inkstone-Token` 头值（见 §3.4）。

### 1.3 并发模型

| 位置 | 模型 |
|---|---|
| sidecar | FastAPI + 单 worker（uvicorn `workers=1`）。文件 IO 用 `anyio.to_thread` 包装阻塞调用，不阻塞事件循环 |
| 写文件 | 同一 chapter 的写操作**串行化**（进程内 `asyncio.Lock` per chapterId） |
| 渲染进程 | 保存请求**串行**（同一时刻最多一个 in-flight PUT） |
| 主进程 | 单线程事件循环，无共享可变状态 |

> **为什么 sidecar 单 worker**：本地单用户场景，多 worker 只会引入文件锁竞争。性能瓶颈在 LLM 调用（M3），到时用 `to_thread` + 连接池解决，不需要多进程。

## 2. 进程与生命周期设计

### 2.1 进程拓扑

```
Electron 主进程
 ├─ 渲染进程（1 个，之后可能按窗口多个）
 ├─ sidecar 子进程（1 个）
 └─ 文件监听（M1 引入）
```

渲染进程不直接持有文件句柄，所有文件操作经 sidecar。

### 2.2 主进程状态机

```
        ┌──────────┐
        │ BOOTING  │  应用启动，读取配置
        └────┬─────┘
             ▼
        ┌──────────┐
        │ SPAWNING │  spawn 子进程，注入 env
        └────┬─────┘
             ▼
        ┌────────────┐  15s 超时
        │ HANDSHAKING├──────────────► FAILED
        └────┬───────┘
             ▼ 收到 INKSTONE_READY
        ┌────────────┐  探活失败 3 次
        │  HEALTHY   ├──────────────► RESTARTING
        └────────────┘                    │
             ▲                            │ 退避 1s/2s/4s
             └────────────────────────────┘
                                          │ 3 次仍失败
                                          ▼
                                       FAILED（终态）
```

状态经 `sidecar:onStatus` 事件广播给渲染进程，驱动启动遮罩 / 错误页。

| 状态 | UI 表现 |
|---|---|
| BOOTING / SPAWNING / HANDSHAKING | 全屏启动遮罩「正在启动本地服务…」 |
| HEALTHY | 正常界面 |
| RESTARTING | 顶部横幅「本地服务已重启，正在恢复…」，编辑器只读 |
| FAILED | 全屏错误页 + 日志路径 + 「重试」按钮 + 「复制诊断信息」 |

### 2.3 握手协议（详细）

**报文格式**（sidecar → 主进程 stdout，单行）：

```
INKSTONE_READY {"v":1,"port":51234,"pid":1234,"version":"0.1.0"}
```

| 字段 | 说明 |
|---|---|
| 前缀 | 固定 `INKSTONE_READY `，含一个空格 |
| v | 协议版本，主进程校验；不支持则视为握手失败并给出明确日志 |
| port | 内核分配的实际监听端口 |
| pid | sidecar 进程号，供主进程强杀使用 |
| version | sidecar 版本，与桌面 app 版本比对，不一致时告警（不阻断） |

**解析要求**：

- 主进程按**行**缓冲解析，不整块等待（sidecar 可能先输出其他日志行）。
- 其余 stdout 行原样转写到 sidecar 日志文件。
- 15 秒内未收到就绪行 → 视为失败，把日志尾部 50 行返回给 UI。

**sidecar 侧实现要点**（Python）：

```python
def serve(app) -> None:
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    sock.bind(("127.0.0.1", 0))        # 内核分配，杜绝竞态
    port = sock.getsockname()[1]
    config = uvicorn.Config(app, log_config=None, access_log=False)
    server = uvicorn.Server(config)
    _announce(port, os.getpid())        # 先宣告再开始 serve
    asyncio.run(server.serve(sockets=[sock]))
```

> ⚠️ 顺序很重要：必须先 `bind` 拿到 socket，再把它交给 uvicorn（`sockets=[sock]`）。若先起 uvicorn 再回头查端口，会拿到 0 或需要轮询。
> ⚠️ 宣告放在 `serve` 之前，主进程才能尽早开始探活。

### 2.4 健康检查与监督

| 参数 | 值 | 理由 |
|---|---|---|
| 探活间隔 | 5s | 本地进程，频率足够 |
| 探活超时 | 2s | 本地回环，超过即异常 |
| 判死阈值 | 连续 3 次失败 | 避免慢启动/GC 抖动误判 |
| 重启退避 | 1s → 2s → 4s | 指数退避，最多 3 次 |
| 重启冷却 | 重启后 10s 内不判死 | 给冷启动留时间 |

**探活实现**：`GET /api/v1/healthz`，2s 超时，不计入日志（避免刷日志）。

### 2.5 退出清理时序

```
app.before-quit
 1. 标记 intentionalShutdown = true       → 防止 supervisor 触发重启
 2. 通知渲染进程 flush 未保存内容（等待最多 2s）
 3. 向 sidecar 发送 SIGTERM（Windows: taskkill /PID <pid> /T /F）
 4. 等待进程退出，最多 3s
 5. 超时 → 强制 kill
 6. event.preventDefault() 在以上完成后调用 → 真正退出
```

> Windows 上 Node 的 `child.kill('SIGTERM')` 不会终止子进程树。必须用 `taskkill /PID <pid> /T /F`，其中 `<pid>` 取自握手报文（不是 spawn 返回的 pid，因为 sidecar 可能是包的包装进程）。

> ⚠️ **实测补充（批次 A 落地时确认）**：Windows 上 venv 的 `Scripts\python.exe` 就是一层 **redirector 包装进程**，它会再拉起真正的解释器。实测数据：`spawn()` 返回 pid `31380`，而 sidecar 内 `os.getpid()` 为 `9868`，且 `os.getppid() == 31380`（包装进程正是真正的父进程）；`sys.executable` 指向 venv 路径，`sys._base_executable` 指向基础解释器。
>
> 由此得出两条硬要求：
> 1. **硬杀必须同时杀两个 pid**（报文 pid + `child.pid`）。只杀报文 pid，包装进程可能赖着不走；只杀 `child.pid`，`/T` 虽能带走后代，但语义上不如前者精确。任一侧残留都会导致 stdio 管道不关、`child.on('exit')` 永不触发，表现为**点关闭后应用卡死**。
> 2. **不要写 `payload.pid === child.pid` 这种断言**。这不是不变量，只是某些环境的巧合；真正的不变量是"杀掉报文 pid，服务就消失，且包装进程随之退出"。

### 2.6 孤儿进程防御（双保险）

**保险一**：主进程退出时 `taskkill /T /F`（见 §2.5）。

**保险二**：sidecar 侧**stdin EOF 探测**。

```python
async def watch_parent_stdin() -> None:
    # 父进程退出时管道关闭，stdin.read() 返回 EOF
    await anyio.to_thread.run_sync(sys.stdin.read)
    logger.warning("parent stdin closed, shutting down")
    os._exit(0)
```

> 为什么不用 `os.getppid()`：Windows 上父进程退出后 `getppid()` 行为不可靠（可能返回原值）。
> 为什么不用轮询 psutil：多一个依赖、多一次系统调用，而 stdin 管道是操作系统级保证，跨平台一致。
> 前提：主进程 spawn 时**必须保留 stdin 管道**（`stdio: ['pipe', 'pipe', 'pipe']`）。

## 3. 安全设计

### 3.1 token 生成与注入

```ts
const token = crypto.randomBytes(32).toString('hex');   // 64 hex chars
spawn(exe, [], {
  stdio: ['pipe', 'pipe', 'pipe'],
  env: {
    ...process.env,
    INKSTONE_TOKEN: token,
    INKSTONE_HOME:  app.getPath('userData'),
    INKSTONE_LOG_DIR: path.join(app.getPath('userData'), 'logs'),
    INKSTONE_PARENT_PID: String(process.pid),
  },
});
```

| 决策 | 理由 |
|---|---|
| token 走 env，不走命令行、不走 stdout | 命令行可见于进程列表；stdout 进日志。env 两者皆不 |
| token 存主进程内存 + 经 preload 注入渲染进程 | 不落磁盘；重启即失效（不持久化，无需轮换机制） |
| 32 字节随机 | 远超本地暴力破解需要 |

### 3.2 鉴权中间件

```python
@app.middleware("http")
async def auth(request: Request, call_next):
    if request.url.path == "/api/v1/healthz":
        return await call_next(request)
    provided = request.headers.get("X-Inkstone-Token", "")
    if not secrets.compare_digest(provided, settings.token):
        return JSONResponse(status_code=401, content={"error": {"code": "UNAUTHORIZED", ...}})
    request.state.trace_id = ulid()
    return await call_next(request)
```

- 用 `secrets.compare_digest` 做常量时间比较。
- 缺失与错误**返回同一响应**，不区分（避免信息泄露）。
- `/healthz` 不校验：需在拿到 token 前就能探活；仅本机可达且只返回 `{ok, version, uptime}`。

### 3.3 绑定与 CORS

- 只 `bind 127.0.0.1`，不使用 `0.0.0.0`。
- CORS 白名单：开发态 `http://localhost:5173`，生产态 `file://`（Electron 渲染进程 origin 为 `file://` 或自定义协议）。
- 生产态建议注册自定义协议 `app://` 而非 `file://`，便于 CORS 与 CSP 收紧（M0 实现为 `file://` + 允许 `null` origin，记入 M4 优化项）。

### 3.4 日志脱敏

```python
REDACT_KEYS = {"token", "authorization", "x-inkstone-token", "api_key"}
```

- 结构化日志写入前递归过滤上述 key（不区分大小写）。
- 异常堆栈中若包含请求头，同样过滤。
- **测试要求**：有一条测试用例断言「任意日志文件内容中不含 token 原值」。

## 4. 数据层设计

### 4.1 路径规则（`domain/paths.py`）

**这是全项目路径规则的唯一定义处。任何模块不得手拼路径。**

```python
class WorkPaths:
    def __init__(self, root: Path) -> None: ...
    root: Path
    work_json: Path          # root/work.json
    outline_dir: Path        # root/outline
    volume_outline_dir: Path # root/outline/卷纲
    manuscript_dir: Path     # root/manuscript
    codex_dir: Path          # root/codex
    snippets_dir: Path       # root/snippets
    styles_dir: Path         # root/styles
    private_dir: Path        # root/.inkstone
    logs_dir: Path           # root/.inkstone/logs
    backups_dir: Path        # root/.inkstone/backups

    def chapter_dir(self, order: int, slug: str) -> Path
    def chapter_md(self, order: int, slug: str) -> Path
    def chapter_meta(self, order: int, slug: str) -> Path
    def parse_chapter_dirname(self, name: str) -> tuple[int, str] | None
```

**目录名规则**：`{order:03d}-{slug}`

- `order`：从 1 开始，3 位零填充；超过 999 自动扩为 4 位（`parse` 用正则 `^(\d{3,})-` 兼容）。
- `slug` 生成：

```python
WINDOWS_RESERVED = {"CON","PRN","AUX","NUL",*(f"COM{i}" for i in range(1,10)),*(f"LPT{i}" for i in range(1,10))}
ILLEGAL = set('<>:"/\\|?*') | {chr(c) for c in range(32)}

def slugify(title: str, max_len: int = 30) -> str:
    s = "".join("" if ch in ILLEGAL else ch for ch in title).strip()
    s = re.sub(r"\s+", "-", s)
    s = s.rstrip(". ")                      # Windows 不允许目录名以点或空格结尾
    s = s[:max_len] or "untitled"
    if s.upper() in WINDOWS_RESERVED:
        s = f"_{s}"
    return s
```

**解析**：

```python
_CHAPTER_DIR_RE = re.compile(r"^(\d{3,})-(.+)$")
```

不匹配的目录被忽略（不报错），但记一条 warn 日志——用户可能在目录里放了别的东西。

### 4.2 `work.json`

```json
{
  "schemaVersion": 1,
  "id": "w_3f9a2c1b0d4e",
  "title": "我的小说",
  "author": "小方同学",
  "genre": "",
  "tags": [],
  "wordGoal": 0,
  "dailyGoal": 4000,
  "createdAt": "2026-09-18T16:49:19+08:00",
  "updatedAt": "2026-09-18T16:49:19+08:00"
}
```

| 规则 | 说明 |
|---|---|
| `schemaVersion` | 必填。未来迁移依据；M0 只认 `1`，未知版本报 `INVALID_PARAM` 并提示 |
| 未知字段 | 读取时**保留**（写回不丢），便于向前兼容 |
| 缺失字段 | 用默认值补齐并写回 |
| 落盘 | 经原子写（§4.4） |

### 4.3 chapter `meta.json`

```json
{
  "schemaVersion": 1,
  "id": "ch_7b1e4a9c2f30",
  "order": 1,
  "status": "draft",
  "pov": null,
  "wordCountCache": 2143,
  "createdAt": "...",
  "updatedAt": "..."
}
```

**核心规则**：**meta.json 不存任何可从正文推导的信息。**

| 存 | 不存 | 理由 |
|---|---|---|
| id、order、status、pov、字缓存 | 标题、正文、场景分隔 | 标题在正文首行（`# 第一章 xxx`）；md 是唯一真源 |

带 `Cache` 后缀的字段语义 = "可随时重建的缓存，读不到就现场算"。

**`id` 为什么必须存在**：目录名会因重排而变（`001-`→`003-`），但 `id` 不变。批注锚点、快照引用、AI 生成记录全部引用 `id`，因此**重排不会让引用失效**。这是"目录名承载人可读排序、id 承载机器引用稳定性"这条设计的落地。

### 4.4 原子写算法

```python
def atomic_write_text(path: Path, text: str, *,
                      encoding: str = "utf-8", retries: int = 3) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    last: Exception | None = None
    for attempt in range(retries):
        fd, tmp = tempfile.mkstemp(dir=path.parent,
                                   prefix=f".{path.name}.", suffix=".tmp")
        try:
            with os.fdopen(fd, "w", encoding=encoding, newline="\n") as f:
                f.write(text)
                f.flush()
                os.fsync(f.fileno())
            os.replace(tmp, path)          # 同卷内原子替换
            return
        except OSError as exc:             # Windows: 目标被占用 → PermissionError
            last = exc
            with suppress(OSError):
                os.unlink(tmp)
            time.sleep(0.1 * (attempt + 1))
    raise WriteFailed(str(last))
```

| 要点 | 说明 |
|---|---|
| `os.replace` 是同卷原子操作 | 因此临时文件**必须**放在目标同目录，不能放系统 temp |
| Windows 特有：目标被其他程序打开时 `os.replace` 抛 `PermissionError` | 用户可能在 VS Code 里开着这个 md。因此需要重试（3 次，100/200/300ms） |
| 重试耗尽 | 抛 `WRITE_FAILED`，前端强提示，**不允许静默继续** |
| 残留清理 | 启动时扫描 `manuscript/**/.?*.tmp`，删除 mtime 超过 1 小时的 |
| 换行 | 显式 `newline="\n"`，防止 Windows 写成 `\r\n` |

### 4.5 内容哈希

```python
def content_hash(raw: bytes) -> str:
    return hashlib.sha256(raw).hexdigest()[:16]
```

**基于原始文件字节**（不是规范化后的文本）。理由：外部编辑器哪怕只多了一个行尾空格，也应当被识别为"文件被改动"，从而触发冲突提示，而不是被规范化悄悄抹平。

### 4.6 章节清单缓存与失效

```
首访问 → 扫描 manuscript/*/meta.json → 构建 [{id, order, dirName, title, status, wordCount}]
       → 缓存（内存，per workId）
失效条件：manuscript 目录的 mtime 变化
      或 收到显式 refresh=true
```

标题需要读 `chapter.md` 首行 → **列表接口只读每个 md 的首行**（不整文件读入），避免大作品列表变慢。首行不是 `# ` 开头时，标题回退为 `未命名`。

> 缓存是**性能优化**，不是真源。任何缓存 miss 都必须能现场重算。

### 4.7 乐观并发控制

```
PUT /works/{workId}/chapters/{chapterId}
req:  { "markdown": "...", "baseHash": "a1b2c3d4e5f60718" }

sidecar:
  lock = locks[chapterId]             # 串行化同章写入
  async with lock:
    disk = read_bytes(md_path)
    if content_hash(disk) != baseHash:
        return 409 EXTERNAL_MODIFIED { diskHash, diskMarkdown, diskSavedAt }
    atomic_write_text(md_path, markdown)
    update meta.wordCountCache / updatedAt
    return { hash: content_hash(markdown.encode()), wordCount, savedAt }
```

`diskMarkdown` 只在冲突时返回（正常路径不返回全文，省带宽）。

## 5. Markdown 适配层详细设计

### 5.1 语法白名单（形式化）

```
Document      := Block*
Block         := Paragraph | Heading | Blockquote | ThematicBreak
Paragraph     := Inline+
Heading       := { level: 1..3, children: Inline+ }        # 仅 ATX（# 开头）
Blockquote    := Block+
ThematicBreak := "---"

Inline        := Text | Strong | Emphasis
Strong        := "**" Inline+ "**"
Emphasis      := "*" Inline+ "*"
Text          := 任意字符（除空白规范化外原样保留）

禁 用：列表 / 表格 / 代码块 / 行内代码 / 链接 / 图片 / HTML / 脚注 / 定义 / setext 标题 / 硬换行
```

**白名单外一律降级为 Text（内容不丢）**，见 §5.6。

> 硬换行（行尾两空格）显式不支持：归一化会 trim 行尾空格，中文小说一段一行，不需要段内换行。

### 5.2 归一化算法 `normalize()`

```ts
export function normalize(md: string): string
```

步骤（顺序不可换）：

1. `\r\n`、`\r` → `\n`
2. 去掉 BOM
3. 每行行尾空白 trim
4. 连续 3 个及以上 `\n` 压成 2 个（即最多一个空行）
5. ATX 标题行**前后**各保证一个空行
6. `ThematicBreak` 统一为 `---`，且前后各保证一个空行
7. 强调标记统一：`__` → `**`，`_` → `*`
8. 文件末尾保证恰好一个 `\n`（空文件除外）

**不变量**：`normalize(normalize(x)) === normalize(x)`（幂等，有 property 测试）。

### 5.3 三条不变量（这是适配层的验收核心）

```
I1  normalize 幂等：      normalize(normalize(md)) === normalize(md)
I2  文件往返稳定：        toMd(fromMd(md)) === normalize(md)
I3  二次往返完全稳定：    toMd(fromMd(normalize(md))) === normalize(md)
```

> I2 允许"首次加载就把文件规范化"，但**只规范化一次**。I3 保证从此不再漂移。
> 实现时 `fromMd` 内部先调 `normalize`，所以实际断言可简化为 `toMd(fromMd(md)) === normalize(md)`。

### 5.4 三个中文特有的坑与解法

**坑一：行首「数字 + 点」被误判为有序列表**

中文小说里 `1. 他说……` 极常见。remark 会解析成 `list` 节点，编辑器里变成缩进条目，语义完全错。

**坑二：行首 `-` `*` `+` 被误判为无序列表**

破折号开头的对白行同样常见。

**坑三：`---` 被当成 setext 标题下划线**

上一行有文字时，`---` 会变成 H2，分隔线消失。

**统一解法：不用转义，用「按原始偏移降级」**（比转义更稳，且不污染用户内容）

```
1. 解析得到 mdast（每个节点带 position.start.offset / position.end.offset）
2. 遍历禁忌节点类型（list / listItem / table / code / inlineCode / html /
   footnoteDefinition / definition / image / link）
3. 对每个禁忌节点：取其 position 覆盖的**原始文本切片**，
   替换为一个 paragraph 节点，内容是该切片（作为纯文本）
4. 再转为 ProseMirror 文档，并记录一条 AdapterWarning
```

这样：

- `1. 他说` → 段落，文本就是 `1. 他说`（用户看到原样）
- `- 他说` → 段落，文本 `- 他说`
- 不会被 setext 抢走，因为 parse 阶段禁用 setext（只认 ATX）

**已知副作用（必须写进文档与 UI 提示）**：降级行里的 `*`、`_` 等标记字符在序列化时会被 remark 转义（`*` → `\*`），这是**正确行为**——因为用户本意就是字面量。首次规范化会引入这些转义，之后稳定（满足 I3）。

### 6.3 自动保存状态机

```
         onChange
  ┌────────────────────► DIRTY
  │                        │
  │      debounce(500ms)   │  或  maxWait(3000ms) 到
  │                        ▼
  │                    SAVING ──── 200 ──► SAVED ──change──► DIRTY
  │                        │
  │                        ├──── 409 ──► CONFLICT
  │                        └──── 5xx ──► ERROR ──retry(手动/3s后一次)──► SAVING
  └────────────────────────┘
                    （SAVING 期间又有 change → 记 pendingChange，完成后立刻再存一轮）
```

**实现要点**：

```ts
class Autosave {
  private state: 'idle' | 'dirty' | 'saving' | 'saved' | 'conflict' | 'error';
  private pendingChange = false;
  private timer: number | null;
  private firstDirtyAt = 0;

  onChange(): void        // 置 dirty，重置 debounce 计时，检查 maxWait
  async flush(): Promise<void>   // 立即保存；章节切换 / 失焦 / 关窗前调用
  onSuccess(): void       // 若 pendingChange 则立刻再存一轮
  onConflict(detail): void
  onError(err): void
}
```

| 关键规则 | 理由 |
|---|---|
| **保存必须串行**（同一时刻最多一个 in-flight PUT） | 两个并发 PUT 可能乱序落盘，导致后写的旧内容覆盖新内容 |
| `debounce 500ms` + `maxWait 3000ms` | 纯防抖在持续输入时永不落盘，崩溃即丢整段 |
| 失焦 / 切换章节 / 关窗前 `flush()` | 这三个是用户认为"已经保存了"的时刻 |
| `pendingChange` 标记 | SAVING 期间的新改动不能丢，必须在完成后补一轮 |
| ERROR 状态不静默 | 顶栏变红 + 「重试」按钮；此时禁止切换章节 |

### 6.4 字数统计

```ts
const WS = /[\s\u3000]/u;             // 含全角空格
const PUNCT_OR_SYMBOL = /[\p{P}\p{S}]/u;

export function countWords(text: string) {
  let withPunct = 0, withoutPunct = 0;
  for (const ch of text) {
    if (WS.test(ch)) continue;
    withPunct++;
    if (!PUNCT_OR_SYMBOL.test(ch)) withoutPunct++;
  }
  return { withPunct, withoutPunct };
}
```

| 口径 | 定义 |
|---|---|
| 含标点 | 非空白字符全部计数（CJK 与拉丁字符均按 1 计） |
| 不含标点 | 再排除 Unicode `P`（标点）与 `S`（符号）类别 |

> 用码点迭代（`for...of`）而非 `length`，避免 emoji / 生僻字的代理对被算成两个。
> 默认展示口径可在设置里切换（M1）；M0 默认"不含标点"，符合网文平台习惯。

### 6.5 章节切换时序（防丢字的关键）

```
用户点击章节 B
 1. if (autosave.state === 'dirty' || 'saving')
        await autosave.flush()
 2. if (flush 失败)  → 中断切换，弹提示：「当前章节保存失败，已阻止切换」
 3. if (saveStatus === 'conflict') → 中断切换，必须先解决冲突
 4. setLoading(true)
 5. GET /works/{w}/chapters/{B}  → 拿 markdown + hash
 6. fromMd(markdown)             → doc；若 warnings 非空 → 显示提示条
 7. editor.commands.setContent(doc, false)   // false = 不触发 onChange
 8. currentChapter = B；autosave.reset(hash)
 9. 光标移至文首；setLoading(false)
```

**第 1~3 步是这个功能的全部价值**。跳过 flush 直接切换，就是"偶发丢字"这类最难查的 bug 的来源。

### 6.6 冲突处理流程（409）

```
收到 EXTERNAL_MODIFIED
 → 暂停自动保存（进入 CONFLICT 态）
 → 弹 <ConflictDialog>，展示：我的版本 / 磁盘版本（按行 diff）
 → 三选一：
    a) 用磁盘版本：setContent(fromMd(diskMarkdown))，丢弃本地改动
    b) 保留我的并覆盖：
         先把磁盘版本原子写到 .inkstone/backups/{chapterId}-{ts}.md
         再 PUT 时用 diskHash 作为 baseHash（强制覆盖）
    c) 另存副本：
         在 manuscript/ 追加新章 {title}-副本，写入我的版本
         当前章切到磁盘版本
 → 结束后重置 autosave（baseHash = 最新 diskHash）
```

**无论选哪条，磁盘上被覆盖的那一版都必须先落到 `.inkstone/backups/`。** 这是"不静默丢用户内容"的底线。

### 6.7 API 客户端封装

```ts
// renderer/src/lib/api.ts
class ApiError extends Error { code: string; detail?: unknown; traceId?: string }
class ApiClient {
  constructor(private conn: { baseUrl: string; token: string }) {}
  request<T>(method, path, body?): Promise<T>     // 自动带 token、归一化错误
  get<T>(path): Promise<T>
  put<T>(path, body): Promise<T>
  post<T>(path, body): Promise<T>
}
```

- 错误一律抛 `ApiError`，`code` 取自信封。
- 401 → 直接进入 FAILED 界面（说明 token 失效，通常是 bug 或应用被外部重启）。
- 不重试写操作（幂等性由 baseHash 保证，重试反而危险）。

## 8. 关键时序

### 8.1 冷启动

| # | 主进程 | sidecar | 渲染进程 |
|---|---|---|---|
| 1 | 读配置、生成 token | — | — |
| 2 | spawn（stdio 全 pipe，env 注入） | 启动，读 env | — |
| 3 | 监听 stdout 行缓冲 | bind `127.0.0.1:0` | 显示启动遮罩 |
| 4 | 解析 `INKSTONE_READY` | 打印就绪行 → `serve()` | — |
| 5 | 建窗口（可先显示遮罩） | 待命 | 请求 `sidecar:getConnection` |
| 6 | 启动探活循环 | 响应 `/healthz` | 拿到连接 → 进入作品列表 |
| 7 | 广播 `HEALTHY` | — | 关闭遮罩 |

### 8.2 编辑与保存

| # | 渲染进程 | sidecar | 磁盘 |
|---|---|---|---|
| 1 | 用户输入 → onChange → DIRTY | — | — |
| 2 | debounce 500ms 或 maxWait 3000ms | — | — |
| 3 | PUT（markdown + baseHash） | 加 chapter 锁 | — |
| 4 | — | 读文件、比 hash | 读 |
| 5 | — | hash 相符 → 原子写 | 写 tmp → fsync → replace |
| 6 | — | 更新 meta 缓存 | 写 meta.json |
| 7 | SAVED（若期间有新改动 → 立刻再存一轮） | 释放锁 | — |

### 8.3 sidecar 崩溃恢复

| # | 主进程 | 渲染进程 |
|---|---|---|
| 1 | 检测子进程 exit（非主动退出） | 收到 `RESTARTING` → 编辑器切只读 + 顶栏横幅 |
| 2 | 退避 1s/2s/4s 后 spawn | 保存中的请求失败 → 保持 DIRTY |
| 3 | 重新握手、探活 | 收到 `HEALTHY` → 自动重试一次保存 |
| 4 | 3 次失败 → `FAILED` | 全屏错误页 + 重试按钮 |

> 崩溃恢复后**必须重新取 token**？不需要——token 由主进程生成，重启的 sidecar 从同一个 env 读取，token 不变。所以渲染进程无需刷新连接信息，只是 baseUrl 的 port 会变（新端口）。**因此渲染进程必须在每次收到 `HEALTHY` 后重新 `sidecar:getConnection`**。这条容易漏，特别标注。

## 10. 打包与运行时

| 项 | 方案 |
|---|---|
| 桌面打包 | electron-builder，target `nsis`（M0 只出 Windows） |
| sidecar 打包 | PyInstaller `--onedir`（不用 `--onefile`：启动快、便于增量更新） |
| 二进制注入 | 构建产物放 `apps/desktop/resources/sidecar/`，打包时经 `extraResources` 带上 |
| 开发态 | 直接调 `.venv/Scripts/python.exe -m inkstone`，不打包，缩短迭代 |
| 路径解析 | 生产态用 `process.resourcesPath`；开发态用仓库相对路径。统一封装在 `main/sidecar/env.ts` |
| 体积预估 | Electron ~180MB + sidecar ~80MB |
| 已知坑 | PyInstaller 打包 FastAPI/uvicorn 需补 hidden-imports（`uvicorn.logging`、`uvicorn.loops.*`、`uvicorn.protocols.*`、`anyio._backends._asyncio`）。**批次 D 第一件事就是跑通打包后启动，不要等到最后** |
