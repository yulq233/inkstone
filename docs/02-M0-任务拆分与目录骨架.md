## 0. M0 定位

### 0.1 一句话目标

**证明骨架跑得通**：新建作品 → 写字 → 落盘 → 关掉重开内容还在 → 用外部编辑器改了文件，应用能感知。

### 0.2 为什么是这个目标

M0 不追求功能数量，只追求把**三个高风险假设**钉死：

| # | 假设 | 不成立会怎样 |
|---|---|---|
| H1 | Electron 主进程 + Python sidecar 在 Windows 上能稳定握手、优雅退出、崩了能自愈 | 整个架构要换（比如改成纯 Node 后端），返工一切 |
| H2 | "文件即真源"经得起外部编辑 —— 用记事本改 md，应用不炸、不覆盖、能感知 | 数据主权这个核心卖点不成立，产品失去立身之本 |
| H3 | Markdown ↔ ProseMirror 的往返无损**可以被机器验证**，而不是靠人工试 | 批注锚点、版本 diff、快照全部建立在不稳的地基上 |

M0 结束时，这三条必须有可复现的证据，而不是"我试了一下没问题"。

### 0.3 验收标准（Definition of Done）

| # | 验收项 | 判定方式 |
|---|---|---|
| A1 | 一条命令进入开发态 | `pnpm dev` 同时拉起 sidecar 与桌面窗口，日志合并到一处 |
| A2 | 新建作品生成完整目录骨架 | 与 §5.1 的结构逐项比对，无缺项 |
| A3 | 连续写 3 章、每章 2000 字以上，切换章节不丢内容 | 三轮往返切换后逐字比对 |
| A4 | 强杀进程（任务管理器结束）后重启，丢失输入 ≤ 3 秒 | 记录最后输入时刻与磁盘内容差异 |
| A5 | 用 VS Code 改 `chapter.md`，应用内提示"文件已被外部修改"，可不覆盖 | 触发 409 分支，选择重载 |
| A6 | 适配层往返测试全绿 | CI 跑 property-based 测试，含随机中文段落 |
| A7 | 启动全程无外网请求 | 抓包或断网启动 |
| A8 | 打包出安装包，安装后能完成 A2~A5 | Windows 上装一遍走通 |

## 2. 关键架构澄清（M0 必须定下来的四件事）

这四条在设计文档里没有细化，但 M0 实现时必须二选一。以下是我的建议与理由。

### 2.1 适配层放在渲染进程，sidecar 只认 Markdown

**决策**：`markdown ↔ prosemirror` 的转换全部在**渲染进程（TypeScript）**完成；sidecar **完全不认识 ProseMirror**，它只处理 Markdown 纯文本。

**理由**：

- ProseMirror 模型只存在于渲染进程。若把转换放 sidecar，每敲一个字都要跨进程 HTTP，延迟不可接受。
- sidecar 的职责收敛为"文本 + 文件 + 索引 + 模型"，与编辑器实现解耦。将来换编辑器内核，sidecar 一行不用改。
- 往返测试用 `vitest + fast-check` 在 TS 侧写，跑得快、进 CI 成本低。

**契约共享方式**：语法白名单定义为一份常量（`packages/shared/src/md-schema.ts`），Python 侧**不做**结构化 Markdown 解析，只做行级统计（字数、段落数）。两侧不共享解析器，只共享"允许哪些语法"这个事实。

> ⚠️ 这一条与设计文档 §3.12 的表述兼容，但更精确：§3.12 说"所有正文读写必须经过适配层"——在 M0 落为"**渲染进程内所有正文读写必须经过 `packages/md-adapter`**"，并加 ESLint 规则禁止绕过。

### 2.2 渲染进程直连 sidecar 的 HTTP，IPC 只管系统能力

**决策**：渲染进程通过 `fetch` / `EventSource` **直接**调 sidecar 的 `127.0.0.1:<port>`；Electron IPC 只承担窗口、菜单、文件对话框、sidecar 生命周期事件。

**理由**：

- 少一层转发，少一层类型映射，调试时能在 DevTools 直接看到请求与响应。
- M3 的流式生成要用 SSE，走直连是天然形态；若走 IPC，需要额外搭事件通道。
- token 由 preload 通过 `contextBridge` 注入渲染进程，安全边界不变（本地应用，威胁模型本就是"本机其他程序"，靠 token + 127.0.0.1 绑定已经封住）。

**代价与约束**：渲染进程持有 token，需确保不写入任何日志、不进入崩溃报告（见 §8 风险）。

### 2.3 启动握手：token 走环境变量，端口走 stdout

**决策**：

```
1. 主进程生成 token = crypto.randomBytes(32).toString('hex')
2. spawn sidecar，token 通过环境变量传入（不写命令行、不落文件）
3. sidecar 自行 bind 127.0.0.1:0，由内核分配端口（避免端口抢占竞态）
4. sidecar 向 stdout 打印一行：INKSTONE_READY {"port":51234,"pid":1234,"version":"0.1.0"}
5. 主进程解析该行 → 探活 GET /healthz → 通过后创建窗口
6. 15 秒未就绪 → 弹窗报错并输出 sidecar 日志尾部
```

**为什么 token 走 env 而不是 stdout**：stdout 会被写进日志文件，token 出现在日志里等于泄露。env 不进日志、不进进程列表。

**为什么端口让 sidecar 自己 bind**：主进程先选端口再传给 sidecar 会有竞态（选完到 bind 之间被别人抢占）。让内核分配是唯一无竞态的做法。注意实现上要**先手动 bind 拿到 socket，再把 socket 交给 uvicorn**，不能先起 uvicorn 再回头查端口。

**退出清理**：主进程在 `before-quit` 里发 `SIGTERM`（Windows 走 `taskkill /PID <pid> /T /F`），等待 3 秒，超时强杀。同时 sidecar 侧启动一个父进程心跳监视：若父进程消失，自行退出，防止孤儿进程。

### 2.4 M0 不做文件监听，用「写时校验」替代

**决策**：M0 不引入 chokidar / watchdog。外部改动通过**乐观并发校验**在保存时发现：

```
PUT /api/v1/chapters/{id}
Body: { markdown, baseHash }
- 磁盘当前文件 hash == baseHash → 写入，返回新 hash
- 不相等 → 返回 409 EXTERNAL_MODIFIED，附磁盘版本内容
```

前端收到 409 时弹出三选一：**重载外部版本** / **覆盖（先自动备份我的版本）** / **另存为副本**。

**理由**：

- 用极小成本覆盖了最关键的风险 —— 不静默覆盖用户在外部编辑器里的改动（对应 H2）。
- 实时监听需要处理"自己写的文件触发自己的事件"这类回环问题，M0 不值得。
- M1 引入 watcher 后，写时校验仍保留作为最后一道保险。

## 5. 接口契约

### 5.1 错误码（`packages/shared/src/errors.ts` 与 Python 侧对齐）

| code | HTTP | 含义 | 前端行为 |
|---|---|---|---|
| `INVALID_PARAM` | 400 | 参数非法 | 提示 |
| `UNAUTHORIZED` | 401 | token 缺失/错误 | 视为致命，提示重启 |
| `WORK_NOT_FOUND` | 404 | 作品不存在 | 回作品列表 |
| `CHAPTER_NOT_FOUND` | 404 | 章节不存在 | 刷新列表 |
| `EXTERNAL_MODIFIED` | 409 | 文件被外部改动 | 弹三选一 |
| `WRITE_FAILED` | 500 | 落盘失败 | 强制提示，禁止继续静默编辑 |

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/healthz` | 就绪探针 |

## 6. 实现要点与已知坑

### 6.1 Markdown 往返的三个坑（必须在 4.7 里处理）

**坑一：数字 + 点开头会被误判为有序列表**

中文小说里 "1. 他说……" 这种行极其常见。 remark 会解析成 ordered list，编辑器里显示成缩进条目，语义完全错了。

> **解法**：解析前对行首匹配 `^(\s*)(\d+)\.\s` 的位置插入转义（`1\. `），解析完成后把该转义还原为纯文本节点；序列化时按同一规则重新转义。保证"往返稳定"且"语义符合预期"。

**坑二：行首 `-` `*` `>` 同理**

以破折号开头的对白行、"*" 开头的强调行，都会被误解析。同坑一处理。

**坑三：`---` 既是分隔线又是 setext 标题下划线**

若上一行有文字，`---` 会被当成 H2 的 setext 下划线。

> **解法**：禁用 setext 标题，只允许 ATX（`#` 开头）；并在归一化阶段确保分隔线前后各有一个空行。

### 6.2 编辑器扩展集 == 语法白名单

TipTap 只加载 `Paragraph / Heading(ATX) / Bold / Italic / Blockquote / HorizontalRule / History`，**不加载** List、CodeBlock、Link、Table、Image。

这样"白名单外的语法"在应用内**根本产生不出来**，只有外部编辑才会引入，走 4.5 的降级路径。语法白名单（`md-schema.ts`）与编辑器扩展集必须同源，用一个常量导出，避免两边漂移。

### 6.3 meta.json 不复制可从正文推导的信息

- 正文（含标题）→ 唯一真源是 `chapter.md`
- `meta.json` 只存：`id`（稳定 UUID，供锚点/快照引用）、`order`、`status`、`pov`、`wordCountCache`（可重建）
- **目录名前缀 `NNN-` 承载人可读的排序**，`id` 承载引用稳定性。重排章节时批量重命名目录，但 `id` 不变，所以批注锚点不会因重排而失效。

### 6.4 自动保存的正确形态

纯防抖会在"持续输入不中断"时永远不落盘（丢了就是整段）。必须 **debounce + maxWait**：

```
变更 → 500ms 静默后写
     → 但距上次写入超过 3000ms 则立即写
失焦 / 切换章节 / 关闭窗口 → 立即写
```

### 6.5 Windows 编码

- 所有文件读写显式 `encoding="utf-8"`，绝不依赖系统默认编码（Windows 默认 GBK，会炸）。
- 路径一律 `pathlib.Path`，不手拼字符串。
- 作品目录可能含中文空格，测试用例必须覆盖。
- 日志用 utf-8 且行尾 `\n`（不要 `\r\n`，避免跨平台比对差异）。

## 8. M0 特有风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Windows 上 sidecar 变孤儿进程 | 用户看不到的进程常驻、端口占用 | 双保险：主进程退出时 `taskkill /T /F`；sidecar 侧监视父进程心跳自退 |
| 端口竞态 | 启动偶发失败，难复现 | sidecar 自行 bind `:0`，不用主进程选端口 |
| token 泄漏进日志 | 本机其他程序可伪装调用 | token 只走 env；日志与错误上报做脱敏；显式测试"日志中不含 token" |
| PyInstaller 打包 FastAPI/uvicorn 缺 hidden-imports | 开发能跑、装了不能跑 | 打包后立刻跑 A8，把打包验证前置到批次 D 的第一件事 |
| 原子写在 Windows 上的行为差异 | 极端情况下仍可能残留临时文件 | 启动时清理 `.tmp.*` 残留；`os.replace` 保证同卷原子 |
| 适配层"看起来无损"但边界有损 | 悄悄改坏用户正文 | property-based 测试 + 至少 200 组随机中文样本；发现降级必须可见（提示用户） |
| 过早引入 SQLite 索引 | 新增"索引与文件不一致"这一类 bug | M0 明确不建库，列表与统计现场读文件 |
| nvm 安装路径含空格 | 构建脚本偶发失败 | 用 pnpm + corepack，不依赖全局 node；脚本内所有路径加引号 |
