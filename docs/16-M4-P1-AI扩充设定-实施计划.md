## 1. 决策记录（动手前定死）

### D-1 独立端点 `/ai/expand`，不并入 `/ai/quick`

`/ai/quick` 的判据是「短文本生成、无选区、同一套装配（光标上下文）与统计」。而 expand：

- **装配源不同**：quick 读「光标前后文 + 设定.md」，expand 读「codex 条目 + 近章原文片段」——把两种装配塞进 `_collect()` 会让分支暴涨；
- **产物语义不同**：quick 产物插回光标处，expand 产物是「候选设定文本」要写回 codex 文件，统计/记录的口径也不同。

结论：独立端点，但**复用** `GenerationService.prepare/events`（生成与流式那半完全一致），只新增「装配」与「端点薄壳」。

### D-2 不改 `ContextBundle` 形状，装配源在 `_collect()` 内部按 task 分流

`ContextBundle` 的 `{system, blocks, user, dropped, budget}` 在 v1 定死，换 v2 只换 `_collect()`。expand 的装配同样是「组装成 blocks + user」，只是 blocks 的来源（codex 条目、原文片段）不同——所以**形状零改动**，`task='expand'` 时走一条新的 `_collect` 分支，产出结构一样的 `ContextBundle`。

### D-3 新增「设定候选」展示组件，不复用 `AiCandidatePanel`

`AiCandidatePanel` 的接受动作是「插入光标处」，且刻意不显示全文（全文在幽灵文本）。expand 的候选必须**显示全文**、采纳动作是「写回 codex 的 summary 或 body 字段」。所以：

- **复用**：`gen-state.ts`（流式状态机 / 首字延迟 / 成本 / 外发统计）、SSE 解析、`use-egress-gate`（外发闸门）。
- **新增**：一个 `SettingCandidatePanel`（全文展示 + 采纳/放弃 + 保留/丢弃），挂在 codex 编辑页内，不占编辑器那条候选条。

### D-4 并发占位键：`<workId>:expand:<type>:<slug>`

续写的 `busy_key = <workId>:<chapterId>` 防「同章同时两次续写」。expand 不绑章节，绑**条目**：`<workId>:expand:<type>:<slug>`——同一张卡同时只跑一次扩充。放同一个 `busy` 表（`WorkRegistry` 既有机制），不用新造。

### D-5 装配源（expand 专用，先限源、再兜底；首版范围见 D-8）

| 来源 | 内容 | 上限 |
| --- | --- | --- |
| 目标条目现值 | summary + fields（键值拼一行）+ body 尾 600 字 | body 截尾 |
| 关联条目 | 目标 `relations` 指到的条目，各取 summary 一行 | 每行 ≤120 字、共 ≤10 条 |
| 总纲 | `outline/总纲.md` 首 1500 字（世界观描述尤其要用） | 截头 |

> ~~近章原文片段~~：首版跳过（D-8）。

### D-6 模板 `expand.toml`：按 `type` + `target`（summary/body）换 prompt

- `[kinds]` 下 `expand` 一个 kind，`type`（character/location/faction/item/concept）与 `target`（summary/body）作为**渲染变量**而非 5×2=10 个模板——同一份骨架，prompt 里按变量换措辞。
- **原样复制原则**（`docs/11` §3.7）：模板文本手写一次钉死，测试断言渲染结果；改动只动模板文件，不动代码。

### D-7 body 采纳 = 追加 + 独立删除（已拍板）

`target=body` 的候选，采纳时**追加到 body 末尾**，保留用户手写草稿；多次生成多次追加。

**独立删除的锚定**：每次追加前插入一行 HTML 注释标记 `<!-- ai:<runId> -->`（runId 复用 `runs.jsonl` 的本次外发记录 id）：

- Markdown 渲染时注释不可见、普通阅读无感，不污染「body 自由文本」的可读性；
- 不与 `frontmatter.py` 识别的 `---` 分隔符冲突（HTML 注释不是 frontmatter 分隔）；
- 「删除该次」= 找到对应 `<!-- ai:runId -->` 到下一个标记（或 body 末尾）之间的文本，整段删除——runId 唯一，精确到「这一次」，不影响手写草稿与其他次追加。

采纳写回时，前端把「候选全文 + 标记」拼成新 body 交给 `use-codex.save`；删除时同理，用纯函数切掉对应段落后再 save。

### D-8 近章原文片段：首版跳过（已拍板）

E1 装配**只喂**「条目现值 + 关联条目 summary + 总纲」，不扫描章节文件找命中片段——降低 E1 复杂度、避开同步扫全文件的 IO（M7 审查项）。真正的 L5 检索留给 M2；E1 收口后视「AI 对作品当前进度了解不足」的实际体验再决定是否补廉价扫描。

## 6. 风险与已知坑（写代码前再读）

1. **`busy_key` 语义变化**：续写的 `<workId>:<chapterId>` 硬编码在 `service.py`，expand 要另起 `<workId>:expand:<type>:<slug>`——别顺手把续写的键也改了，那是 M4/M7 审查修过的并发守卫。
2. **preview 的三条 E35 断言不能破坏**：expand 的 preview 路径必须走 `preview()`（不出网/不落记录/不占并发位），别为图省事复用 `prepare`（那是「真的要发」）。
3. **`extra="forbid"`**：`ExpandRequestIn` 别回灌派生字段；渲染层构造请求体要剥掉 slug/hash（B1/B3 踩过的坑）。
4. **~~近章原文扫描的性能~~（N/A）**：D-8 已决定首版跳过近章扫描，本条暂不适用。将来恢复时记住：文件名扫描是 O(章节数 × 条目数)，P0 章节几十、条目几十可接受；但**别**在装配里同步扫全文——走 `anyio.to_thread`（M7 阻塞 IO 审查项）。
5. **候选不显示全文的旧组件别误用**：`AiCandidatePanel` 接受动作是「插光标」，expand 用它会插进编辑器正文——务必用新的 `SettingCandidatePanel`。
6. **采纳写回 body 的语义**：body 是自由草稿，采纳是「追加」还是「替换」要定死（D-7 待拍板），否则用户点了「生成描述」把辛苦写的草稿冲掉。
7. **装配读磁盘、编辑页有本地态 —— 二者会脱节**（首轮真机已踩，见 §9）：用户改了输入框但没保存就生成，AI 拿到的是旧值。**别**用「把本地态塞进请求体」来修（等于未保存内容静默出网，与"默认只存在本机"的文案冲突）；正确姿势是**生成前先落盘**（B/C 已实现）。任何依赖「条目现值」的新动作都要考虑这一层。

## 8. E2 落地实测（写 E3 / 后续批次前必读）

1. **`use-expand` 不复用 `gen-state` 的 reducer**（见 §5 偏差）。它在 `delta` 里只往
   `textRef` 累加 + 排一次 `TEXT_THROTTLE_MS=80` 的刷新，`done`/`error`/停止时立即 flush。
   不节流的话，面板每帧 `setState` 会把同一页里的**一整排受控输入框**一起 diff。
2. **采纳 / 删除必须立即落盘，不能只改本地态**。两个理由不同：
   - 候选是**瞬态**的（关掉面板就没了），不落盘 = 白生成；
   - 「删除该次」若只改本地态，用户点「← 返回」（`codex.close()` 不保存）时那段文字会
     **静默复原** —— 他以为删掉了。
   所以两者共用 `EntryDetail` 的 `persist()`，它返回 `boolean`，失败时**不收面板**
   （用户能重试；原因已在错误条上）。
3. **`EntryDetail` 保存后不重挂载 → 必须回填本地态**。`key` 是 `codex.current.slug`，
   `codex.save` 只换 hash 不换 slug，所以组件不重挂载；`persist()` 成功里那句
   `setSummary` / `setBody` **不能省** —— 省了输入框显示旧值，用户再点「保存」会把
   刚采纳的内容覆盖回去。
4. **`.primary` 不是全局类**。别处都是 `.ai-panel-actions button.primary` 这种限定写法，
   所以在 `codex.css` 里补了 `.codex-candidate-actions button.primary`。
5. **codex.css / outline.css 里 `var(--fg)` / `var(--muted)` 是死变量**（真源是
   `--text` / `--text-muted`），声明会被整条丢弃、颜色退化成继承。新代码一律用正确变量；
   老代码待单独一次真机核对再统一修（已在该 css 末尾留待办注释）。
6. **`expand` 的 `intent`（补充说明）暂无 UI 入口**。`start(target, intent?)` 与
   `AiExpandRequest.intent` 都已支持、`expand.toml` 也留了 `{intent}` 变量，但
   `docs/16` §3.1 只定了两个按钮，所以 UI 不传 —— 与 `useAiQuick.start(kind, intent?)`
   同样"接口先留、UI 后置"的形态。

## 9. 首轮真机缺陷与修复（B + C，2026-09-30）

### 9.1 现象

用户在「女主」卡的「一句话梗概」输入框里把名字改成 **「沈念」**（**未点保存**），随即点
「生成描述」。AI 候选写出来的人物叫 **「林悠然」** —— 既不是输入框里的「沈念」，也不是
磁盘上的「女主」，是凭空编的第三个人名。

### 9.2 根因（两侧，缺一不可）

| 侧 | 根因 | 证据 |
| --- | --- | --- |
| **装配** | expand 的**唯一真源是磁盘**：`buildExpandRequest` 只带 `type`/`slug`，sidecar 回读 `codex/<type>/<slug>.md` 装配。**编辑页里未保存的改动永远不会进 prompt** —— 用户以为 AI 读的是眼前界面，其实读的是最后一次落盘的内容 | `_collect_expand()` 读 `codex_store`；渲染层请求体无字段承载本地态 |
| **prompt** | 原 `expand.toml` system 没有明确「**要扩充的这条设定自身的名称是既定事实**」。模型把「给『女主』起个名字」当成一项待补全的细节，于是自作主张起名 | `expand.toml` v1 system 全文 |

> ⚠️ 两侧必须都修：只修 prompt（B）治不了「AI 读到的是旧名字」这一层；只修 UI（C）治不了
> 模型即便拿到「沈念」仍可能另起别名。

### 9.3 修法

**B — prompt 加固**（`prompts/expand.toml`，`version` 1 → 2）：

system 从 5 条扩到 6 条，新增第 3 条（原 3/4/5 顺延）：

```
3. **要扩充的这条设定本身的名称是既定事实**（在用户消息「当前设定条目」一节里、单独成行用【】括起来的那个）：
   直接沿用它，不要给它改名、不要另起别名，也不要把"给它取个名字"当成一项待补全的细节。
   即使那个名字看起来只是个职能代称（例如"女主""男配"），也照原样沿用 —— 替它编一个新名字是最严重的错误。
```

- `version` 升号的理由：`version` 是元数据、落进 `runs.jsonl` 的 `templateVersion`，**改 prompt
  语义必须升版本**，否则历史记录里分不清「这条外发用的是哪版 system」。`load_template` 只校验
  `("id","version","temperature","system","user")` 必填，升号不影响加载。
- ⚠️ system **不做变量替换**（`_render_system` 只 `template.system.strip()` + 可选 style_card /
  continue intent），所以**不能写 `{entry}`**，只能用文字指代「用【】括起来的那条」。这是本条
  措辞绕的原因。

**C — UI 拦截**（`CodexPanel.tsx` / `codex-model.ts` / `codex.css`）：

- **C-1 纯逻辑**：`codex-model.ts` 新增 `EntryFormValues` + `isEntryDirty(form, saved)` —— 逐项比
  `name/aliases/tags/summary/body` + `stableJson(fields)`（**键序无关**，只用于比较，别用裸
  `JSON.stringify`——对象键序变化会误判为脏）。
- **C-2 交互**：`EntryDetail` 加 `dirty` memo；`startExpand(target)` 在 `dirty` 时**先 `persist()`
  落盘再生成**（落盘失败则不发请求）；按钮下方常驻一行提示 `.codex-expand-hint`：「AI 只读取
  **已保存**的设定。你有未保存的改动，生成前会先自动保存。」
  - 提示用 **`--text-muted` 普通色**，**不是错误色** —— 这不是错误，是告知。用错误色会让用户
    以为做错了什么。
  - 提示仅在 `dirty && !expandRunning` 时出现。

### 9.4 验收与回归

- **sidecar**：新增 `test_expand_system_pins_entry_name_as_ground_truth` —— 钉住 system 里有
  「既定事实 / 不要给它改名 / 照原样沿用」三段，并钉住 `{entry}` **不在 system**（`_render_system`
  不做变量替换，写进去会原样发给模型）。同时把 `test_ai_expand_context.py` / `test_ai_expand_api.py`
  里两条 `template_version == 1` 断言改 `== 2`（升版是**有意**的，测试跟着走才是对的）。
- **desktop**：`codex-model.test.ts` 新增 10 条 `isEntryDirty`（含 **fields 键序不同不脏**、嵌套对象键序不同
  不脏、列表顺序不同脏）。
- `docs/12` 新增 **G13** 作为回归闸门（未保存 → 有提示 → 生成前先落盘 → 候选名字与输入框一致）。
- 变异验证（两处都已还原）：
  - **B**：删掉 `expand.toml` system 第 3 条 → 新用例红（`assert '既定事实' in template.system` 失败）。
  - **C**：把 `stableJson` 换成裸 `JSON.stringify` → 「键序不同不脏」2 条红；去掉 `name` 比较 →
    「名字改了 → 脏」红。

### 9.5 未做（本轮边界）

- **不改装配源**：没有把「编辑页本地态」塞进请求体。理由——那会让「未保存内容出网」变成静默行为，
  与「正文与设定默认只存在本机」的文案冲突；正确做法是**先保存再生成**（C 走的就是这条）。
- **不做「生成前预览将发送什么」**：那是 P1-b 3b 的「首发云端确认卡」增强项，后置（见 `docs/10`
  §11.8 与 `docs/14` §4.8）。
