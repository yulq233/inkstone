### T16 修 CI 的 Python job（`taskkill` 平台问题）

| 项 | 内容 |
| --- | --- |
| 依据 | T5 的实跑结论；`services/sidecar/tests/test_handshake.py:271`；`docs/08` §7 的预案 |
| 现象 | `test_hardkill_by_announced_pid_terminates_everything` 在 `ubuntu-latest` 上必挂 → Python job 恒红（Node job 不受影响） |
| 修法 A（推荐） | 给那条用例加 `@pytest.mark.skipif(sys.platform != "win32", reason=…)` —— 它验的**本就是 Windows 的进程树行为**（venv 的 `python.exe` 是 redirector 包装进程，所以 `taskkill /T /F` 要同时杀两个 pid）。Linux 上这个前提根本不存在，跳过是**如实**而不是掩盖 |
| 修法 B | CI 的 pytest 步加 `-k "not test_hardkill_by_announced_pid"`（`docs/08` §7 的预案写法）。能解，但把"该不该在 Linux 上跑"这件事藏进了 workflow 文件 |
| 为什么不选 `-k "not handshake"` | 会把 `test_parent_death_leaves_no_orphan`、`test_shutdown_endpoint_exits_cleanly`、`test_token_never_appears_in_process_output` 等**在 Linux 上应该跑**的用例一起跳过，覆盖面白丢 |
| 前置 | 无。但**改完必须 push 一次**才能验证（CI 只在 push / PR 时触发） |
| 判据 | push 后两个 job 全绿 |
