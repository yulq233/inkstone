## 1. 决策记录（动手前定死，别在代码里临时发挥）

### D-1 frontmatter 解析：sidecar 新增 `pyyaml`，渲染层零 YAML

- 人物卡 = **单文件**（frontmatter 结构化 + 正文自由描述），这是 `docs/14` §4.1 已确认的形态；拆成 `meta.json + body.md` 两个文件会破坏"一张卡一个文件、外部编辑器打开全都在"的可移植性卖点。
- 解析器选型：**不手写**。`fields` 是开放键值 + 中文键 + 列表 + `relations` 嵌套对象，手写 parser 是 bug 农场；`pyyaml` 纯 Python 可跑、PyInstaller 打包成熟。代价 = sidecar 多一个运行时依赖，**必须同步登记**：
  - `pyproject.toml` dependencies；
  - PyInstaller 依赖守卫（`docs/13` M30 那套）跟着加，否则"开发机好好的、装完报 ModuleNotFound"。
- dump 规则钉死：`yaml.safe_dump(..., sort_keys=False, allow_unicode=True, default_flow_style=False)` —— `sort_keys=False` 保字段顺序（人读的文件别被字典序搅乱）、`allow_unicode=True` 保中文原样。**往返不变性**用 property 测试钉住（§5）。
- 渲染层**永远不解析 YAML**：sidecar 解好成 JSON，前端只收发 JSON。前端出现 yaml 依赖 = 设计被违反，code review 拦下。

### D-2 slug 即人物卡文件名，冲突加短后缀

- `codex/character/<slug>.md` —— **目录名就是 type 字面量**（`character` / `location` / `faction` / `item` / `concept`，全是**单数**），落点 = `codex/<type>/<slug>.md`，与 `docs/14` §4.11 C1 对齐。（⚠️ 早期文档写过复数 `characters/`，与实现不符，已于 2026-09-30 全仓改正 —— 真源是 `domain/codex.py` 的 `CODEX_TYPES` + `codex_store.py` 的 `paths.codex_dir / entry.type`。）
- `<slug>` 复用 `paths.py` 的 `slugify(name)`；重名 → 后缀 `-2`、`-3`（**不**用随机 hash —— 人读的目录名要能猜）。
- 改名 = 新 slug 新文件 + 删旧文件，在同一段锁里完成；`relations` 里指向旧 slug 的引用**不改**（进"断链清单"返回给前端提示，不静默改写别人卡片的数据）。

### D-3 章纲文件名 = `<chapterId>.md`，放 `outline/章纲/`

- 放 `manuscript/<章目录>/` 里生命周期自动跟随的方案被否：**删章 = 静默删掉章纲**，违反 `docs/01`"失效进待办、不静默丢弃"与决议③的"孤儿标记不删"。
- 文件名用稳定 id 而不是 `NNN-slug`：章纲被"机器引用"的键就是 chapterId，目录名前缀那份"人读的排序信息"渲染时 join 章节清单即可——这正是 `paths.py` 模块注释里写的分工，别把两套信息搅在一个文件名里。
- 新增 `paths.py` 常量：`CHAPTER_OUTLINE_DIR = "章纲"`、`GENERAL_OUTLINE_MD = "总纲.md"`，加进 `WorkPaths`（照旧：**任何模块不得手拼路径**）。

### D-4 乐观并发：GET 带 `hash`，PUT 带 `ifMatch`，不匹配 409

- 章节已有外部改动检测（sha256）。codex/outline 同样会被外部编辑器改，且**没有**章节那套"工作会话"上下文，冲突只能靠预条件。
- 复用 `atomic.py` 的 `content_hash`；语义与章节一致（409 = `conflict`），前端复用既有冲突提示组件的文案模式。

### D-5 伏笔住在章纲 frontmatter 里，不建独立文件

- 伏笔天然跨章（埋在 A 章收在 B 章），但它的**登记动作**发生在"写某章的纲"时；独立文件（`伏笔.json`）违反 md 真源约定，独立 md 又难结构化。
- 章纲 frontmatter 的 `foreshadow` 列表是唯一登记口；清单与超期提醒 = **扫描聚合**（GET `/foreshadows`），不落派生文件（`.inkstone/` 也不落——P0 数据量小，现场扫）。`status: open | resolved | dropped` 由用户手动改；**P0 不做任何自动回收判定**（那是 P2 语义复核的事）。

### D-6 起名器纯本地、无数据文件

- 姓氏表 + 名字音节库硬编码在 TS 模块里（公有领域常用字），组合生成 + "避免与现有人物重名"校验（对照 codex 清单）。
- 不引词典文件、不做五行八字——P0 它是个灵感抽签，不是命理工具。

## 2. sidecar 文件层与 API

### 2.1 数据模型（`inkstone/codex/model.py`，pydantic）

```python
class Relation(BaseModel):
    to: str          # 对方 slug
    kind: str        # 父子/同僚/敌对…… 自由文本
    note: str = ""

class CodexEntry(BaseModel):
    type: Literal["character", "location", "faction", "item", "concept"]
    name: str
    aliases: list[str] = []
    tags: list[str] = []
    fields: dict[str, Any] = {}      # 开放键值；中文键合法
    summary: str = ""                # P1 才进 prompt，P0 只是普通字段
    relations: list[Relation] = []
    body: str                        # frontmatter 之后的自由描述
    # 派生（不落盘）：slug, hash
```

校验规则：`name` 非空 ≤200；`fields` 深度 ≤2、单键 ≤100 字（防有人把正文塞进键值）；`to` 必须是合法 slug 字符集。

### 2.2 outline 数据模型（`inkstone/outline/model.py`）

| 对象 | 文件 | frontmatter |
| --- | --- | --- |
| 总纲 | `outline/总纲.md` | 无（纯正文） |
| 卷纲 | `outline/卷纲/NNN-<slug>.md` | `{ order, title }`（`NNN` 与 order 双写一致，照章节目录的既有双写约定，重排时同步） |
| 章纲 | `outline/章纲/<chapterId>.md` | `{ chapterId, foreshadow: [...] }` |

`Foreshadow`：`{ id, title, expectResolveBy: str|None, status, resolvedIn: str|None }`；`id` = `fs-` + 短随机（`domain/ids.py` 现成）。

### 2.3 端点（`api/v1/codex.py`、`api/v1/outline.py`，全部照 `chapters.py` 的鉴权/错误语义）

```
GET    /works/{wid}/codex                          → 清单（含 hash，不含 body）
POST   /works/{wid}/codex                          → 新建（name+type → slugify，冲突加后缀）
GET    /works/{wid}/codex/{type}/{slug}            → 全量
PUT    /works/{wid}/codex/{type}/{slug}            → 全量替换，ifMatch 预条件
DELETE /works/{wid}/codex/{type}/{slug}            → 删除
GET    /works/{wid}/codex/broken-relations         → 断链清单（D-2）
GET    /works/{wid}/outline/general                → 总纲（不存在 = 200 空正文，不 404：总纲是"必然要写"的）
PUT    /works/{wid}/outline/general                → ifMatch
GET    /works/{wid}/outline/volumes                → 卷纲清单
POST   /works/{wid}/outline/volumes                → 新建卷（分配末位 order）
PUT    /works/{wid}/outline/volumes/{order}        → ifMatch；order 变更 = 重排目录名
DELETE /works/{wid}/outline/volumes/{order}
GET    /works/{wid}/outline/chapters/{cid}         → 章纲（不存在 = 200 空壳，带 chapterId）
PUT    /works/{wid}/outline/chapters/{cid}         → 校验 cid 存在于章节清单，否则 404
GET    /works/{wid}/foreshadows                    → 扫描聚合 + 超期标记（now > expectResolveBy 且 open）
```

### 2.4 并发与 IO

- 锁粒度：per-work 一把 `asyncio.Lock` 管 codex 与 outline 全部写（两者都轻量，不细分到 slug 级；别为不存在的并发造两把锁的顺序问题）。
- 阻塞 IO 全部 `anyio.to_thread`（照 repo 模块注释的既有约定）；写走 `atomic_write_text`（M13 原子写 + fsync 白捡）。

## 6. 风险与已知坑（写代码前再读一遍）

1. **pyyaml 打包**：PyInstaller 对 `yaml` 有隐藏导入的坑（CDLL 加载失败时回落纯 Python）——冒烟脚本（步骤 07 那套 18 项）必须补一条"安装包里 codex 端点可用"。
2. **中文目录名**：`卷纲/章纲` 在 NTFS 没问题（`001-第一章` 已验证过），但**测试断言里路径拼接必须走 `WorkPaths`**，谁手拼字符串谁 review 拦下。
3. **`outline/` 老作品兼容**：目录早已建好但为空——清单端点对空目录返回空数组而非 404；`总纲.md` 不存在时 GET 返回空正文（2.3 已定），前端显示"还没写总纲"引导态。
4. **UTF-8 无 BOM + LF**：照 `docs/08` 的行尾约定，`atomic_write_text` 已保证；别在新代码里 `open(..., "w")` 不带 `newline="\n"`。
5. **别复制 autosave**：3.3 的理由；谁想在 P0 加自动保存，先回答"低频结构化编辑要哪条自动保存的收益"。
6. **B1 实测补充（2026-09-29）**：① `--basetemp` 的**父目录必须先存在**，否则 `tmp_path` 全体 `ERROR at setup`（症状与 docs/08 §11.4 相同，成因不同——这次是 `.pytmp/` 本身没建）；② PUT 契约里**没有** slug/hash（服务端派生字段），客户端回灌读取结果会被 `extra="forbid"` 拦成 400 —— B3 的前端要记得剥掉再发。
7. **B2 实测补充（2026-09-30）—— CRLF 是必须容忍的输入**：Windows 的 `Path.write_text` 默认把 `\n` 写成 `\r\n`，外部编辑器/记事本也是。frontmatter 拆装若用 `"---\n"` 死匹配分隔符，CRLF 文件**整个打不开**（症状是"章纲/人物卡读取返回空"）。已把拆装抽成 `domain/frontmatter.py` 统一容忍 CRLF：**只归一化 frontmatter 段用于匹配分隔符，body 原样保留**（改 body 行尾 = hash 变 = 假冲突）。回归测试钉在 `test_codex_model.py::test_parse_tolerates_crlf_line_endings`。
8. **B3 实测补充（2026-09-30）—— `react-hooks/set-state-in-effect` 是纯静态的**：新版 eslint-plugin-react-hooks 这条规则**不追踪参数分支**，只要 effect 调用的函数体内**任意一处**有同步 setState（哪怕只在 `if (!initial)` 里、effect 实际传 `true` 绕过），就标记。绕不过去，只能①把 effect 要调的那个函数拆成「`await` 前零 setState」的独立函数（`use-codex.ts` 的 `initialLoad`），②在该 effect 行加精确 `eslint-disable-next-line` 并写明"setState 全在 promise 回调里、不级联"的理由。项目既有 5 条同类 warning 同源（`use-chapter-switch`/`use-work-entry`/`use-api-client`/`WorkShell`），本轮**没新增**。另：`prettier --write` 是硬门槛——`format:check` 会把任何手写文件打回，收尾前务必对新增/改动文件跑一遍。
9. **B4 实测补充（2026-09-30）**：① **卷纲清单项不含 body**（`_load_volume_item` 只回 order/title/slug/hash，与 codex 清单同一条"清单不放大字段"纪律）——点进单卷编辑必须再走 `GET /volumes/{order}` 读全量，前端 `use-outline.readVolume` 在**事件处理器**里读（不是 effect，避免又踩 set-state-in-effect）。② **伏笔的 `overdue`/`orphan` 是 sidecar 现算的**（`_foreshadows_sync`），前端 `outline-model.ts` 只做"翻译成文案"，**不重复实现判定**——否则两处必然漂移。③ 章纲跟当前章走：`use-outline` 收 `chapterId`，切章靠 `loadChapter` effect 跟随（await 前零 setState）；组件层用 `chapter.chapterId !== chapterId` 判"正在加载新章"，避免切章瞬间把上一章的纲显示成当前章的。

## 7. 明确不做（P0 边界，越过即跑偏）

- 不碰 `inkstone/ai/*` 与装配器（P1）；不做编辑器内提及高亮（M2）；不做 AI 候选/闸门接线（P1）。

- 不做关系网图形化（决议①）；不做章纲↔正文偏离提示（B2，P2）。
- 不做多选批量操作、拖拽排序（卷纲排序用上移/下移按钮即可）。
