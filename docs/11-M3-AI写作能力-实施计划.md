## 2. 目标与非目标

### 2.1 v1 AI 目标（可验收）

1. 用户在设置里填一个模型（BYOK 或本机 Ollama），点「测试连接」**当场可用**。
2. 在正文任意位置 `Ctrl+Enter` 续写：**流式**出字、可随时停、停在哪儿就留到哪儿。
3. 选中一段文字，能被**改写 / 扩写 / 缩写 / 润色 / 去 AI 味**，给出**候选 + diff**，可部分接受。
4. 「快捷生成」：斜杠指令 + 快捷键 + 选中浮现，覆盖起名、对白、场景、章末钩子、卡文救济。
5. 每次生成都留下一条 `ai_run`（模型、耗时、token、成本、是否采纳）—— **可回溯、可统计采纳率**。
6. **正文不被 AI 意外污染**：未采纳的生成不落盘、不进撤销栈、不触发自动保存。

### 2.2 明确不做（沿用 `docs/01` §1.4 / §6.4）

- ❌ 一键生成整本书（批量节点**每一处都要人工确认**）
- ❌ 云同步 / 账号体系 / 移动端
- ❌ 自己训练或微调模型
- ❌ 供 `docs/01` 附录 C 的开放问题（模型评测、版权归属）在本文档定论

### 2.3 隐私红线：AI 是**第一个真正外传数据**的模块

`docs/01` §9.3 已经定好了三条措施与一句文案边界。AI 必须**逐条兑现**，不能等 M2 的检索那套一起做：

| `docs/01` §9.3 的既有要求 | AI 侧的具体落点 | 阶段 |
|---|---|---|
| 提供「**纯本地模式**」，一键禁止所有外发请求 | `AiSettings.offlineOnly: boolean`。**必须在网关单点拦截**（`gateway.stream()` 入口就拒），不能在各个调用点各判一次 —— 漏一处就等于没做 | P0 |
| 条目级 `visibility: 私密` **不进入云端 prompt** | 装配器**在装配时**过滤（不是在上游过滤）。本机模型（`local: true`）不受此项限制 | P3（依赖 Codex） |
| **出网审计**：记录时间 / 提供方 / 外发字符量，面板可查可导出 | `ai_run` 增记 `egressChars` 与 `providerId`，`/ai/runs` 即审计数据源；AI 设置页有「外发记录」面板，支持导出 JSON/CSV | P1 |
| 文案边界 | 统一表述：**「正文与设定默认只存在本机，索引可选用云端加速。」** AI 相关文案**不得**写成"所有数据默认不出本机" | P0 |

另外两条 AI 专属的知情要求：

- 首次启用某个**非本机**供应商时，必须弹一次「**将发送什么**」确认卡（可展开看真实 payload 预览）；
- 供应商列表里 `local: true`（Ollama）的项**不弹**，并标「本机模型·不外传」。

> 这条不是"合规点缀"：AI 会让"正文片段离开本机"从**可选**（M2 的云端 embedding）变成**每次生成都发生**。
> 把知情与控制做进 P0/P1，是唯一不至于事后返工的顺序。

## 3. 架构设计

### 3.1 数据流总览

```
渲染进程（React）
  AI 面板 / 指令菜单 / 幽灵文本 / 候选卡
        │  ① fetch + ReadableStream（带 token 头）
        │     POST /api/v1/ai/continue  →  SSE: meta / delta / usage / done / error
        ▼
sidecar（FastAPI）
  api/v1/ai.py           路由层：只表达"发生了什么"
  ai/gateway.py          ModelGateway：按 routing 选模型 → 流式调用 → 归一化 chunk
  ai/context.py          上下文装配器：产出 ContextBundle（分层、带预算审计）
  ai/prompts/            YAML 模板（版本化，变量占位）
  ai/runs.py             ai_run 记录（JSONL 追加）
        │  ② httpx.AsyncClient（stream=True）
        ▼
  OpenAI 兼容端点 / Ollama / (未来) Dify

主进程（Node）
  safeStorage ── 加密存 Key；解密后经本地 HTTP 推给 sidecar（内存）──▶ ③
```

### 3.2 为什么 AI 走 sidecar 的 SSE，而不是 IPC

| 方案 | 否决理由 |
|---|---|
| 主进程转发 | 多一跳、DevTools 看不到流、主进程要处理长连接与背压 —— 与 `docs/02` §2.2"IPC 只管系统能力"冲突 |
| `EventSource` | **不能设自定义请求头** → 过不了 `x-inkstone-token` 中间件，直接 401 |
| 轮询 | 流式的体验全丢，且长任务要靠状态表 |

**结论：`fetch` + `res.body.getReader()` 手写 SSE 解析。** 唯一新增的客户端能力。

> ⚠️ **坑（必须记）**：`lib/api.ts` 的 `request()` 硬编码了 `AbortSignal.timeout(10_000)`。
> AI 生成 30~120s 是常态，**绝不能复用它** —— 10 秒必被掐断，而且报出来的是 `NETWORK` 错误，
> 看起来像"sidecar 挂了"。要新增 `streamPost()`，超时策略是"**无总超时，只有用户主动中止 + 首个 chunk 的 60s 超时**"
> （首 chunk 超时能区分"模型挂了"与"模型在思考"）。

### 3.3 凭据管理：Key 绝不落盘明文

| 环节 | 做法 | 理由 |
|---|---|---|
| 存储 | 主进程 `safeStorage.encryptString()` → `<userData>/credentials.enc` | Electron 内置，Windows 走 DPAPI、macOS 走 Keychain，**不引入 keytar**（久未维护、原生依赖会拖累 PyInstaller 之外的打包） |
| 可用性 | `safeStorage.isEncryptionAvailable() === false` 时（Linux 无 keyring）→ **拒绝存储**并提示改用环境变量 | 假加密比不加密更危险：用户以为存好了 |
| 使用 | 主进程解密 → `POST /api/v1/ai/credentials`（本地回环 + token）→ sidecar **仅存内存** | sidecar 重启即失效，由主进程在握手完成后重推一次 |
| 落盘 | `settings.json` 里**只有** `providerId` / `baseUrl` / `hasCredential: boolean` | 渲染进程拿不到 key，也不该拿到 |
| 日志 | 统一脱敏函数：任何 `sk-`/`Bearer` 形态的串在写日志前替换为 `<redacted>` | 日志会被用户贴到 issue 里 |

> ⚠️ 真实取舍：这条路把 Key 短时经过渲染进程内存（用户在自己输入框里打的字）。
> 想彻底避开就得让**主进程直接打 sidecar**，但那会破坏"渲染进程直连"的架构一致性，
> 且要为主进程再写一套 HTTP 客户端。**v1 接受这个取舍**，理由是同一用户同一台机器，
> 且 sidecar 与主进程都在本机回环。写在这里是为了让它是一个**有意识的选择**，不是疏忽。

### 3.4 模型网关：v1 自研薄网关（OpenAI 兼容优先），LiteLLM 后置

`docs/01` §4.2 选了 LiteLLM。**建议 v1 不引入**，理由：

| 维度 | 自研薄网关 | LiteLLM |
|---|---|---|
| 覆盖面 | OpenAI 兼容协议**一家打通**：Qwen(百炼兼容) / DeepSeek / Kimi / GLM / MiniMax / SiliconFlow / 火山 / Ollama / 各类中转 | 覆盖更广（含 Anthropic 原生、Bedrock、Vertex） |
| 依赖体积 | ~0（复用 `httpx`） | 大量依赖，PyInstaller 体积与构建时间明显上升 |
| 可控性 | chunk 归一化、错误码映射、用量统计都能按我们的契约写 | 要适配它的抽象，出问题要读它的源码 |
| 风险 | 非兼容协议要自己写适配 | 版本迭代快，锁定成本 |

**判据（写成代码注释，别凭感觉）**：出现以下任一情况才引入 LiteLLM ——
① 需要 ≥2 个**非 OpenAI 兼容**协议；② 需要跨供应商自动 fallback 链；③ 需要它的成本/用量报表。

**同理不引入 LangGraph**（`docs/01` §4.2 也把它定位在"复杂链路"）：
判据是出现「生成 → 校验 → 修复」闭环，或 ≥3 步带条件分支的链路。v1 的续写/改写都是**单步**。

**网关接口（定死）**：

```python
class ModelGateway(Protocol):
    async def list_models(self, provider: ProviderConfig) -> list[ModelSpec]: ...
    async def test(self, provider: ProviderConfig, model: str) -> TestResult: ...

    def stream(
        self,
        req: ChatRequest,          # messages + 采样参数 + 归一化后的选项
    ) -> AsyncIterator[Chunk]:     # Chunk = Meta | Delta | Usage | Done | Error
        ...
```

**按任务分模型（routing）**（`docs/01` §4.3）：`continue / rewrite / quick / outline / summarize / check`
六个槽位，默认值给好，允许用户改。摘要类默认落便宜模型，校验类默认落推理型。

**采样参数默认值**（`docs/01` §8.5）：续写 `temperature 0.75`、改写 `0.6`、起名 `1.0`、校审 `0.1`。

### 3.5 上下文装配器：**接口先定死，实现分两版**

这是本计划最重要的一处设计。`docs/01` §8.1 的记忆金字塔里，L0/L1/L2/L5 都依赖 **Codex + 分层摘要 + 检索**，
而它们属于 **M2，一行代码都没有**。如果坚持"装配器做齐了再开 AI"，AI 就得等两个里程碑。

所以：

| 版本 | 组件 | 依赖 | 何时可用 |
|---|---|---|---|
| **v1 装配器（无索引）** | 系统指令(风格卡+禁止项) + 本章 `prefix/suffix`(L4) + **相邻章节尾部若干字**(L3 的廉价替代) + 手工「作品设定」文件 | 只需 M0 的正文读写 | **立刻** |
| **v2 装配器（金字塔）** | 上述 + L0 Codex 精选 + L1/L2 摘要 + L5 混合检索 | M2 | M2 完成后 |

**接口（v1 就定死，之后不改）**：

```python
@dataclass(frozen=True, slots=True)
class ContextBundle:
    system: str           # 系统指令 + 风格卡 + 禁止项
    blocks: list[Block]   # 每块带 source(L0..L5/manual) 与 token 估算
    user: str             # 用户指令
    dropped: list[Drop]   # 因预算被丢掉的块（**必须回报给 UI**）
    budget: BudgetReport  # 预算 / 实占 / 余量

async def assemble(self, req: AssembleRequest) -> ContextBundle: ...
```

> **为什么 `dropped` 必须存在**：模型写崩时，用户第一个问题是"它到底看到了什么"。
> 只给一个总数等于不给。UI 上要能展开看"本次实际发送的内容"，并标出被丢弃的块。
> 这也正好满足 §2.3 的隐私要求 —— 一份数据两个用途。

**装配器还要承担两道隐私过滤**（`docs/01` §9.3，见 §2.3）：

1. 目标供应商 `local: false` 时，**丢弃** `visibility: 私密` 的 Codex 条目 ——
   在装配层丢，不在上游丢（上游丢的话，模型会"看见但装作没看见"，而我们无从审计）。
2. `offlineOnly === true` 时，装配器**根本不该被调用**（网关在入口就拒）。装配器不重复判这一条，
   但要在 `dropped` 里留一个 `reason: 'offline'` 的类型，以防将来判据前移。

**风格卡（Style Profile）**：`docs/01` §3.7.4。v1 先做**手工可编辑的风格卡**（几百字的文本），
自动统计（句长分布、虚词偏好、对话占比）放 P3，与 M2 的分析能力一起。

### 3.6 AI 运行记录（`ai_run`）：先用 JSONL

`docs/01` §3.7.2 / §5.1 里 `ai_run` 是一张表，但 SQLite 是 M2 的事。v1：

```
<作品目录>/.inkstone/ai/runs.jsonl     一行一条，只追加
```

字段（**命名与 `docs/01` §5.1 的 `ai_run` 表逐列对齐**，这样 M2 建库时是纯搬运；`camelCase` 只是 JSONL 的写法）：

```json
{"id":"r_...","workId":"w_...","at":"2026-09-28T05:00:00Z","taskType":"continue",
 "targetRef":"chapter:c_...","selection":{"from":120,"to":480},
 "providerId":"deepseek","model":"deepseek-chat",
 "promptDigest":"sha256:...","contextTokens":1832,"outputTokens":412,
 "egressChars":3210,"costCny":0.0031,"latencyMs":4210,"firstTokenMs":680,
 "accepted":"full","acceptedChars":412,"stopped":false,"error":null}
```

| 字段 | 与 §5.1 的对应 | 说明 |
|---|---|---|
| `taskType` | `task_type` | `continue/rewrite/expand/condense/polish/deai/quick/outline` |
| `targetRef` | `target_ref` | `chapter:<id>` 或 `work:<id>` |
| `promptDigest` | `prompt_digest` | **只存摘要（脱敏），不存 prompt 正文** |
| `contextTokens` / `outputTokens` | 同名 | |
| `egressChars` | *新增* | **外发字符量** —— §9.3 要求的外发审计靠它。这是 `docs/01` 表里没有、但 AI 必须补的一列 |
| `costCny` | *新增* | 按 `ModelSpec` 价格估算，未知为 `null` |

- **不记录完整 prompt 正文**（体积 + 隐私），只记 `promptDigest` 与 token 数；
  完整 prompt 只在用户手动"导出诊断包"时落盘。
- `accepted` 分三态 + `acceptedChars` → 采纳率与"AI 到底有没有帮上忙"的唯一硬指标。
- 迁移策略：M2 建 SQLite 时写一个一次性导入器把 JSONL 灌进表，**JSONL 保留为审计流**
 （`egressChars` 这条审计需求要求它不可被覆盖式写入）。

## 4. 数据与契约

### 4.1 新增共享类型 `packages/shared/src/ai-types.ts`

```ts
export type ProviderKind = 'openai-compatible' | 'ollama' | 'anthropic' | 'dify';

export interface ModelProvider {
  id: string;
  kind: ProviderKind;
  label: string;
  baseUrl: string;
  /** Key 是否已配置。**真值在主进程，这里只有布尔** */
  hasCredential: boolean;
  /** 本机模型（不外传）—— 决定隐私文案与首次确认卡是否弹出 */
  local: boolean;
}

export interface ModelSpec {
  id: string;
  providerId: string;
  label: string;
  contextWindow: number;
  maxOutput: number;
  /** 每千 token 价格（元）。中转/自建价格不同，允许用户改；未知为 null */
  pricePerKIn: number | null;
  pricePerKOut: number | null;
}

/** 按任务分模型（docs/01 §4.3） */
export interface AiRouting {
  continue: string; rewrite: string; quick: string;
  outline: string; summarize: string; check: string;
}

export type AiTask = 'continue' | 'rewrite' | 'deai' | 'quick' | 'outline';

export interface AiGenRequest {
  workId: string;
  chapterId: string;
  /** 光标前文（渲染进程从编辑器取，sidecar 读不到未落盘内容） */
  prefix: string;
```

> `_normalize_finish_reason`）：上游的 `content_filter` / `tool_calls` / `end_turn` /
> `stop_sequence` 等方言在这里被收敛 —— 非 `stop`/`length` 一律落 `stop`，

> 归一化不能后置到渲染进程：渲染进程对不认识的值报协议错误，而带 `finish_reason`
> 的那帧是**最后一帧**，会整段不可采纳（见 `docs/13` H3）。

### 4.2 新增错误码（两侧同时加，`docs/03` §1.2 的表要同步）

| code | HTTP | 说明 | 用户能做什么 |
|---|---|---|---|
| `AI_NOT_CONFIGURED` | 400 | 没有可用供应商 / 模型 | 打开 AI 设置 |
| `AI_CREDENTIAL_MISSING` | 400 | Key 没配或已失效（sidecar 内存里没有） | 重填 Key |
| `AI_AUTH_FAILED` | 401* | 上游鉴权失败（与本地 token 无关，**详情里带 upstream 状态码**） | 检查 Key |
| `AI_RATE_LIMITED` | 429 | 上游限流/额度耗尽 | 换模型或等一会儿 |
| `AI_UPSTREAM_ERROR` | 502 | 上游 5xx / 协议不符 | 重试、换模型 |
| `AI_TIMEOUT` | 504 | 首 chunk 超时 | 重试 |
| `AI_ABORTED` | 499* | 用户主动停止（**不算错误**，UI 不报警） | — |
| `AI_BUDGET_EXCEEDED` | 429 | 超出单日预算 | 调预算或换便宜模型 |
| `AI_OFFLINE_ONLY` | 403 | 已开启纯本地模式，云端供应商不可用 | 关闭纯本地模式，或改用本机模型 |
| `AI_CONTEXT_TOO_LONG` | 413 | 装配后仍超上下文 | 换大上下文模型 / 缩短选区 |

> ⚠️ `AI_AUTH_FAILED` 绝**不能**复用 `UNAUTHORIZED`：那会让渲染进程的 `ApiError.isUnauthorized`
> 判成"本地 token 失效"→ 直接进 FAILED 界面。这是最容易踩的一个坑，必须在 `errors.py` 注释里写明。

## 6. 交互设计

### 6.1 幽灵文本（Ghost Text）：Decoration，**不写文档**

- 用 ProseMirror 的 `Decoration.widget` / 行内 decoration 渲染半透明预览。
- **绝不能**先 `insertContent` 再撤销 —— 那会：① 触发 `onUpdate` → `Autosave.mustSave` 置脏 →
  用户看到"已保存"里混进 AI 草稿；② 污染 `prosemirror-history` 的撤销栈；
  ③ 万一崩溃，草稿留在磁盘上。**这是硬要求，不是优化**。
- 生成中：光标处显示流式文本 + 「停止」（`AbortController`），停止后**已生成部分保留**（`docs/01` §3.7.2）。
- 接受：`editor.chain().focus().insertContentAt(pos, content).run()` —— **一次 `run()` = 一个 transaction = 一次 Ctrl+Z**。

### 6.2 候选与 diff

- 改写类任务返回 **1~3 个候选**（同一 prompt 多次采样或不同 temperature）。
- 每个候选：`原文 | 候选` 双栏 diff，行内高亮增删。
- **部分接受**：按段落切分，用户逐段勾选 → 拼装 → 一次事务写入。
- 拒绝：不留痕、不写盘、`ai_run` 记 `accepted: 'none'`。

### 6.3 快捷生成（"快捷生成文字"的落点）

四条入口，覆盖"手不想离开键盘"的场景：

| 入口 | 形态 | 说明 |
|---|---|---|
| **斜杠指令** | 行首/行内输入 `/` → 弹出指令菜单 | TipTap `Suggestion` 插件；`/续写`、`/扩写`、`/起名`、`/对白`、`/钩子`、`/走向` |
| **快捷键** | `Ctrl+Enter` 续写；`Ctrl+Shift+K` 指令面板；`Ctrl+J` 对选中内容操作 | 经 `AppCommand` 下发（主进程只发命令，不碰业务状态） |
| **选中浮现** | 选中文字后浮出小工具条（润色/扩写/缩写/去 AI 味） | `BubbleMenu` |
| **静默提示** | 停笔 3s 后在光标旁给一个极轻的提示点，**默认关闭** | 避免打扰；设置里可开 |

> 斜杠指令的候选列表要**同时列快捷键**，否则用户永远学不会第二条路径。

### 6.4 上下文预览与成本提示

- 生成**开始前**可选弹一次「将发送什么」：分组展示（系统指令 / L4 前文 / 设定 / 检索命中），
  每块显示 token 估算与被截断的部分。
- 生成**之后**在候选卡底部显示：模型名、耗时、token、**估算成本**、首字延迟。
- 超出单日预算 → 生成前弹一次确认（不是硬阻断，`docs/01` §8.5 的"成本护栏"是"告警+确认"）。

### 6.5 失败与中断的界面语义

| 情况 | 界面 |
|---|---|
| 首 chunk 超时 | 幽灵文本位显示一行可重试的错误；**不弹模态框** |
| 上游 401 | 明确指向"模型 Key 无效"，附一个「打开 AI 设置」按钮，并 log traceId |
| 用户停止 | 不算错误：已生成部分转为候选，`stopped: true` |
| sidecar 中途重启 | 流断 → 同"首 chunk 超时"，但错误文案点明"本地服务已重启" |

所有错误都要走 `[renderer] error` 通道（`docs/09` §13.4），否则又是一次"什么都不说的白屏"。

### 6.6 撤销语义

- 接受生成 = **一个事务** → 一次 `Ctrl+Z` 撤销全部。
- 部分接受 = 拼装后**一个事务**（不是逐段插入）。
- 菜单的撤销/重做继续走 `editor.commands.undo()`（`docs/09` §4.3 的结论不变）。

### 6.7 隐私控制面板（AI 数据流）

设置页的「AI 模型」分区里常驻一块，**不是折叠在深处**：

| 控件 | 作用 |
|---|---|
| **纯本地模式** 开关 | 写 `AiSettings.offlineOnly`。开启时云端供应商全部置灰并说明原因；正在进行的云端生成不受影响（不打断用户），但下一次直接拒绝 |
| 当前默认供应商 + 「本机/云端」标记 | 一眼看清"现在写的东西会不会出门" |
| **外发记录**表 | 时间 / 提供方 / 模型 / 外发字符量 / 估算成本；来自 `/ai/runs`；支持导出 JSON/CSV |
| 「将发送什么」预览 | 与 §6.4 同一份组件，可随时手动打开（不必等下一次生成） |
| 文案 | 固定为「正文与设定默认只存在本机，索引可选用云端加速。」（§2.3） |

**实现中查出的两个真缺陷**（都不是 AI 功能本身，而是**被 AI 功能踩到的既有代码**）：

1. **`_on_validation_error` 会把调用方提交的原文回显回去**（`app.py`）。
   在 `/ai/config` 上多传一个字段做验证时，400 的响应体里**原样带出了明文 API Key**

   那里**没有** `scrub()`。修法：`_validation_detail()` 只保留 `loc` / `msg` / `type`。

**预览"三件刻意不做"**（都有自动化断言，见 §8.6）：不占并发位（`_busy`）、不查预算（`_guard_budget`）、

混进用户从未发送过的条目，整份记录就不再可信。

**`needsConfirm` 的四条判据由服务端一处算完**：

```

if self.offline_blocks(p):    return False   # 反正发不出去，别让用户先确认再被拒
return provider.id not in self.acked_egress_providers
```

放服务端而不是渲染进程，是因为它依赖 **`resolve_route()` 的结果**（"这个任务最终会用哪一家"
只有 sidecar 知道：`routing[task]` 优先、为 null 时回落默认）。渲染进程自己判会造出第二份实现，
而两份一定会漂移 —— 症状是"预览说不用确认、生成却换了另一家"。

**实现中实测出的两个坑**：

1. **判定函数必须把 `client` 一起返回**。`admitEgressCheck` 最初只回 `'ignore' | 'bypass' | 'preview'`，
   于是调用方在 `'preview'` 分支里用不了 `client` —— TypeScript **看不出**"'preview' 蕴含 client 非空"
   这层关系。当时的两条退路都有害：再写一次 `if (client === null) return;`（永不执行的死分支），
   或者上非空断言（把类型安全丢掉）。改成返回 `{ kind: 'preview', client: C }` 之后两头都干净
   —— 顺带让这个纯模块对 `C` 泛型化，**零运行时依赖**，纯 node 测试可以直接 import。
2. **"稳定排序"那条注释曾经是错的**。`orderPreviewBlocks` 写成 decorate-sort-undecorate，
   注释理由是"裸 `sort` 会丢掉未知槽位之间的相对顺序"。变异验证时把它换成 `[...blocks].sort(cmp)`
   —— 测试**没有变红**。查下来是 ES2019 起 `Array.prototype.sort` **保证稳定**，两者行为相同，
   那是一次**等价变异**。注释已按事实重写：保留 decorate 形式的真正理由是"**不去改调用方的数组**"
   （把它换成就地 `blocks.sort(cmp)` 立刻变红），而"排末尾"这条性质两种写法都成立。

### 8.4 审查修复落地：AI 流式链路可观测性（M3 / M4 / M7）

**来源**：`docs/13` 第 5 批后续组 · 第二组。这三条同源 —— 都在 **sidecar 侧发请求/写流** 这条链上，
共同点是「**一个失败必须能被看出来**」：要么让失败变成用户可读的错误，要么让失败**别冒充成功**。

**改动落点**：

| # | 文件 | 改了什么 |
|---|---|---|
| M3 | `ai/gateway.py` | ① 流式路径的状态判断 `>= 400` → `>= 300`（3xx 不再被当成"空成功"）；② 新增 `_HTTPX_ERRORS = (httpx.HTTPError, httpx.InvalidURL)`，三处 `except` 全换掉 |
| M4 | `ai/service.py` | ① `events()` 在 `except DomainError` 之外补一档 `except Exception` → 吐 `INTERNAL` 帧并落日志；② `finally` 里的 `_record(...)` 包 try/except，**只记日志、不再抛** |
| M7 | `storage/repo.py` + `works.py` + `app.py` + `ai/usage.py` | `WorkRegistry.recent/remove_recent` 改 `async`（`anyio.to_thread`），另留同步入口 `recent_entries()` 给"已在线程池里"的调用方 |

**M3 的两半（为什么少一半都不行）**：

1. **3xx 不是成功**。`httpx` 默认 `follow_redirects=False` —— 这**正是我们要的**（跟随会把
   `Authorization: Bearer <key>` 发到重定向目标）。但"不跟随"就必须"自己判错"：原来只判
   `>= 400`，3xx 被放过 → 拿到的是重定向页 body → 一行 `data:` 都没有 → 空循环跑完 →
   发 `StreamDone("stop")` → 界面显示「生成完成」、正文一个字没有、`runs.jsonl` 里也是成功。
   **静默的空成功比报错更难查**。修法是把 3xx 也纳入错误分支，并在提示里带上 `Location`
   （"上游把请求重定向到了别处（→ …），这个地址多半不是模型接口"——**把可自修的线索给用户**）。
2. **`InvalidURL` 不是 `HTTPError` 的子类**。实测 `httpx 0.28.1`：
   `issubclass(httpx.InvalidURL, httpx.HTTPError) is False`（MRO = `InvalidURL → Exception`）。所以三处
   `except httpx.HTTPError` 全接不住 —— 用户把 base_url 填成 `http://[::1]:not-a-port/v1` 时，
   会一路逃到 FastAPI 变成 **500**，而它其实是**用户自己能改的配置错误**。修法是单列 `InvalidURL`
   并映射成可读的地址错误。（同类坑：`'not a url'` 抛的是 `UnsupportedProtocol`，那**是** `HTTPError`，
   所以只有"像 URL 但不合法"的输入才会漏。）

**M4 的两半（为什么两个 `except` 位置都要动）**：

1. **响应体里逃逸的异常不会变成 4xx/5xx**。响应头早发出去了，异常只能让 SSE 流**无声断掉**；
   而记录里 `error` 保持 `null` → 失败**看起来是成功的**（审计最不能有的偏差）。修法是在
   `events()` 里兜一档通用 `except Exception`，**自成一帧 `error`/`INTERNAL`**，让客户端和
   `runs.jsonl` 都能看出"这次是失败的"。
2. **`finally` 里抛出的异常会替换正在传播的那一个**。此刻传播的可能是 `CancelledError`
   （用户点了停止），被 `_record` 的写盘异常换成 `WriteFailed` 后，上游再也分不清"取消"与
   "磁盘故障"。修法是 `_record` 自己 try/except，写盘失败只记日志、不改写传播中的异常。

**M7 的根因与修法（为什么不是"在路由里包一层"）**：

`WorkRegistry` 的方法原来是**同步**的，直接读盘。阻塞 IO 的正确修法不是在**每个路由**里包
`anyio.to_thread` —— **下个新路由还会忘**。正确形态是让 `async` 成为 `WorkRegistry` 的**对外承诺**：
类自己把阻塞操作丢进 `anyio.to_thread`，调用方只需 `await`。唯一例外是 `app.py::_recent_roots()`
（它**已经**在线程池里跑，没法再 `await`），所以额外留一个同步入口 `recent_entries()` 给它。
`ai/usage.py::today()` 的 `_roots()` 同理 —— 它把"不阻塞"收进本类，而不是指望每个调用方自觉。

**测试**（sidecar +8）：

| 文件 | 新增 | 钉住的行为 |
|---|---|---|
| `test_ai_gateway.py` | 4 | `InvalidURL` 不是 `HTTPError`（`assert not issubclass(...)`）/ `InvalidURL` 映射成可读地址错误 / 流式路径 3xx 被拒而非静默空成功 / 非流式路径 3xx 同样被拒 |
| `test_ai_stream.py` | 2 | 响应体里抛异常仍产出 `error`/`INTERNAL` 帧且 `runs.jsonl` 记 `error == "INTERNAL"` / `_record` 写盘失败**不替换** `CancelledError` |
| `test_ai_runs.py` | 1 | `_roots()` 在**非主线程**被调用（阻塞 IO 已离开事件循环线程） |
| `test_recent.py` | 1 | `recent/remove_recent` 是协程函数、`recent_entries` 仍是同步函数 |

> **为什么 M7 只能断言"在哪个线程"**：事件循环被阻塞在快机器上**测不出来**（几百微秒的读盘谁都发现不了）。
> 但"注入的函数在**哪个线程**被调用"是**确定性**的，而它**正是修复的全部内容** —— 断言线程，
> 就是断言"阻塞 IO 已经离开事件循环"。

### 8.5 审查修复落地：提示模板与隐私开关（M8 / M9）

**来源**：`docs/13` 第 5 批后续组 · 第三组。这两条都在 §3.7（提示模板）与 §6.7（隐私控制）
落笔时**没写进设计**的边界，属于"实现先于文档想清楚"的地方。

**M8 · 模板 id 的路径穿越（`ai/prompts/__init__.py`）**

`load_template(template_id)` 把 id 拼进资源文件名，而 `importlib.resources.files(pkg).joinpath()`
**不做任何净化** —— 只要 id 里能出现 `/`、`\` 或 `.`，`../` 就能读到包外任意文件
（`.toml` 后缀不是防线）。当前调用方只传路由里写死的常量，但"当前调用方传常量"
是一条**会被改掉**的前提（`§4.3` 明说"加一种快捷生成不该改 Python"，
将来完全可能把 `kind` 直接当 id 用）。

修法是**形状白名单**，不是枚举已知 id：

```python
_TEMPLATE_ID_RE = re.compile(r"^[a-z][a-z0-9_-]{0,63}$")
```

为什么不用 `{"continue", "quick"}`：那会把"新增一个模板文件"变成"改一处 Python"，
与 §4.3 的模板/代码解耦直接冲突。形状约束把危险输入挡在外面，同时不限制合法 id 增长。
检查放在**拼路径之前**（不做"先拼再看在不在"那种 TOCTOU 味道的兜底）。

**M9 · 隐私开关可被持 token 者关掉（设计层，已确认 + 部分补强）**

审查时留了个前置问题：**"取决于 token 是否下发到渲染层"**。本次查清了：

- **token 确实下发到渲染层**——渲染进程**直连** sidecar 是既定架构（§4.2 的 `/ai/*`
  与 §7.2 的连接信息 IPC），`preload` 的 `getConnection()` 返回 `baseUrl + token`。
  所以"渲染进程持 token"不是疏忽，是设计。

于是这条要分两半看，不能笼统说"防住了"或"防不住"：

| 半 | 状态 |
|---|---|
| **fail-open**（漏推配置 → 隐私开关被默认为关） | **P0 已防住**：`AiConfigRequestIn` 八个字段全必填、刻意不给默认值 → 漏推变成响亮的 400，`apply()` 根本不会被调用，sidecar 保留上一份（其中 `offline_only` 仍为 `True`）。理由见 §7.2 |
| **被推着关**（XSS 拿着 token 推一份 `offlineOnly: false`） | **防不住，属架构性残留风险**：sidecar 无法区分"用户关的"与"被推着关的"——同一个 token、同一条回环请求。真正有效的是**渲染进程不跑不可信内容**（CSP 已在步骤 07 落地）+ 不加载远程页面 |

能做且做了的补强是**不静默**：`offline_only` 由 `True` 转 `False` 时单独打一条 `WARNING`
（"纯本地模式已被关闭：此后生成可能把正文发往云端供应商"），让它至少在
`<userData>/logs/sidecar.log` 里留下痕迹。两个细节：

1. **要先记旧值**（`was_offline_only = state.offline_only`）—— `apply()` 之后就只剩新值，
   而"由开转关"这个**方向**才是要留痕的东西；
2. **没有方向变化不重复报** —— 否则每次推配置来一条，等于把这条日志淹掉。

> **要真正消掉这一半**，方向是"把隐私开关从渲染进程可推的配置里**移出去**"
> （改由主进程独占，走一条独立通道）。那要动 §4.2 的契约，属单独排期，不塞进本轮。
> 记在这里是为了下次有人问"为什么 XSS 能关掉纯本地模式"时，答案在文档里而不是在脑子里。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **AI 幻觉引入新设定** | 越写越乱 | 约束前置（仅用已知设定）+ 采纳后入校验队列 + 新增实体需人工确认入库（`docs/01` §11 已有） |
| **上下文成本失控** | 用户被账单吓到 | 单次/单日预算 + 生成前预览 + 每次显示估算成本；摘要类任务默认便宜模型 |
| **隐私事故**（正文外传未告知） | 触碰产品红线 | §2.3 的首次确认卡 + 上下文预览 + 供应商标"本机/云端" + 外发审计面板 |
| **`offlineOnly` 被绕过**（漏判一处调用点） | 用户以为"已禁止外发"但实际发出去了 —— 比没有开关更糟 | 拦截放**网关单点**（`gateway.stream()` 入口）；单测直接断言"开启后任何 provider 都抛 `AI_OFFLINE_ONLY`"；禁用态在 UI 上明确可读 |
| **AI 草稿污染正文** | 数据事故 | 幽灵文本不写文档（§6.1）+ 专门的验收项（P1 验收 3） |
| **边写边生成的卡顿** | 编辑器掉帧 | 流式 chunk 用 `requestAnimationFrame` 批处理落 DOM；装饰只用 `widget`，不做全文档重算 |
| **供应商协议变更/停服** | 功能不可用 | 网关做成薄适配层；`AI_UPSTREAM_ERROR` 明确指向供应商；routing 可随手换模型 |
| **两路生成同时改同一章** | 数据错乱 | 按 `chapterId` 加互斥（§8.3） |
| **PyInstaller 打包体积** | 安装包变大 | v1 不引入 LiteLLM/LangGraph（§3.4）；打包验收里加"安装包体积"这一项 |
| **撤销栈被 AI 事务打碎** | 用户体验崩坏 | 接受 = 单事务（§6.6），并写进单测 |
