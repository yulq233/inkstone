## 0. 为什么排在这里，而不是第一步

| 理由 | 说明 |
|---|---|
| **规则要一次配准** | 在空代码库上配 lint，规则严宽全靠猜；等步骤 01~04 写完，有一万三千行真实代码可以一次调到位 |
| **CI 保护的是"已有的东西"** | CI 建早了只能保护一个骨架；建在功能闭环之后，立刻能拦住后续所有回归 |
| **`no-floating-promises` 的价值兑现点在这里** | 这条规则专门抓"忘了 `await flush()`" —— 而 flush 是步骤 04 才引入的。放在这里，规则一装上就能对刚写完的切章时序生效 |
| **避免"为了过 lint 而反复改配置"** | 先有代码再配规则，一次跑通；反过来会陷入"改代码 → 又发现规则不合适 → 改配置"的循环 |

## 3. mypy 设计（含实测基线）

### 3.1 实测：`--strict` 报 7 条，配好插件后 5 条

```bash
# 未配插件
mypy src --strict        →  7 errors

# 配 [tool.mypy] plugins = ["pydantic.mypy"]
mypy src --strict        →  5 errors
```

### 3.2 那 2 条消失的，是**误报** —— 这条最容易把人带偏

```
error: Unexpected keyword argument "word_goal" for "WorkMeta"; did you mean "wordGoal"?  [call-arg]
error: Unexpected keyword argument "word_count_cache" for "ChapterMeta"; did you mean "wordCountCache"?  [call-arg]
```

`WorkMeta` 的字段是 **snake_case**（`word_goal`），落盘走 alias 的 camelCase（`wordGoal`），并且显式配了 `populate_by_name=True`：

```python
model_config = ConfigDict(extra="allow", populate_by_name=True)
word_goal: int = Field(default=0, alias="wordGoal")
```

所以 `WorkMeta(word_goal=...)` 是**正确写法**。mypy 只认 alias，是因为缺 `pydantic.mypy` 插件 —— 插件会读取 `populate_by_name`，两种名字都接受。加上插件后这两条立即消失（已实测）。

> ⚠️ **危险之处**：mypy 的提示语是"did you mean wordGoal?"，一个不知情的人会照着改。而 camelCase 在 `populate_by_name=True` 下**也能工作**，改完测试还是全绿 —— 问题被彻底掩盖，直到某天有人关掉 `populate_by_name`，或者换个不读 alias 的工具链，才成片地炸。**所以这条规则是：看到 pydantic 模型的 kwarg 报错，先查 alias 与 `populate_by_name`，别改代码。**

### 3.3 剩下 5 条：分类与修法

| # | 位置 | 性质 | 修法 |
|---|---|---|---|
| 1 | `storage/recent.py:92` | **真问题**：类里有个 `def list(self, ...)` 方法，于是同一类内注解 `list[dict[str, Any]]` 里的 `list` 被解析成**那个方法**而不是内置类型 | 把方法名 `list` 改掉（`list_entries` / `all_entries`），同步改 3 处调用点。方法名遮蔽内置名，是这种错误唯一的成因 |
| 2 | `api/v1/works.py:18` | 框架摩擦：Starlette 的 `app.state` 是动态属性，类型上就是 `Any` | `return cast(WorkRegistry, request.app.state.registry)`；在文件头 `from typing import cast` |
| 3 | `api/v1/chapters.py:18` | 同 #2 | 同上 |
| 4 | `app.py:42` | 类型不完整：`-> dict` | `-> dict[str, Any]` |
| 5 | `app.py:43` | 类型不完整：`body: dict` | `body: dict[str, Any]` |

**工作量：5 处、约 20 行以内。** 这条基线很重要 —— 它说明"从零上 mypy 严格模式"在本项目不是一件苦活，因为 sidecar 的代码本来就有完整标注。

### 3.4 配置

写在 `services/sidecar/pyproject.toml`：

```toml
[tool.mypy]
python_version = "3.12"
strict = true
plugins = ["pydantic.mypy"]

# 测试代码放宽：不强制标注 fixture 返回值、允许 Any
[[tool.mypy.overrides]]
module = "tests.*"
disallow_untyped_defs = false
disallow_any_expr = false
```

`plugins` 那一行**不能省**（§3.2）。`python_version` 定 3.12 而实际跑 3.13 —— 与 `pyproject` 的 `requires-python = ">=3.12"` 对齐，取最保守的下限。

`mypy` 加进 `[project.optional-dependencies].dev`。

### 3.5 测试代码也要过

`tests/` 一起纳入（用 overrides 放宽）。理由：测试里写错的类型标注（比如 `dict` 当成 `dict[str, Any]`）同样会误导人，而 pytest 不会报。

## 4. ESLint 设计（含一个会卡住进度的版本冲突）

### 4.1 实测版本（2026-09-20 查 npm registry）

| 包 | latest | peer 要求 | 与 ESLint 10 兼容 |
|---|---|---|---|
| `eslint` | 10.11.0 | — | — |
| `@eslint/js` | 10.0.1 | `^10.0.0` | ✔ |
| `typescript-eslint` | 8.70.0 | `eslint: ^8.57 \|\| ^9 \|\| ^10`；**`typescript: >=4.8.4 <6.1.0`** | eslint ✔ / **typescript ✗** |
| `eslint-plugin-react-hooks` | 7.1.1 | 含 `^10.0.0` | ✔ |
| `eslint-plugin-react` | 7.37.5 | 最高 `^9.7` | ✗ **不支持 ESLint 10** |
| `eslint-config-prettier` | 10.1.8 | `>=7.0.0` | ✔ |
| `prettier` | 3.9.8 | — | — |

**两个冲突**：

1. **`eslint-plugin-react` 不支持 ESLint 10**（peer 最高 `^9.7`）
2. **`typescript-eslint` 的 TypeScript peer 上限是 `<6.1.0`，而本项目用 TypeScript 7.0.2**

### 4.2 决策

**跳过 `eslint-plugin-react`。** 项目全是函数组件 + TS，该插件的主要价值（`prop-types`、`jsx-key`）在 TS 下由编译器覆盖。少一个依赖还顺带躲开冲突 1。

**`typescript-eslint` 照装，但按"能跑则用、不能跑则退"落地**（冲突 2 无法静态判定，只能实测）：

```
第一步：装最小集合，跑通再说
  eslint@10  @eslint/js@10  typescript-eslint@8.70  eslint-plugin-react-hooks@7.1.1  eslint-config-prettier@10

第二步：在根 package.json 里显式豁免 TS 的 peer
  "pnpm": {
    "peerDependencyRules": {
      "allowedVersions": { "typescript-eslint>typescript": "7" }
    }
  }

第三步：验证类型感知规则能否工作
  npx eslint apps/desktop/src/renderer/src/lib/autosave.ts
  ├─ 正常出结果 → 保留 typescript-eslint，并且把 no-floating-promises 设成 error
  └─ 内部报错（TS 7 的 API 不兼容）→ 走退路：卸掉 typescript-eslint，
     只用 @eslint/js + react-hooks + 下面 §4.3 的自定义规则，类型正确性交给已经跑着的 tsc --noEmit
```

**为什么值得为 `typescript-eslint` 折腾**：它带来 `no-floating-promises`，而这条规则正对着本项目的核心风险 —— 步骤 04 的切章时序里"忘了 `await flush()`"是一个**语法上完全合法、跑起来也不报错、只是偶尔丢字**的错误。这正是 lint 该管的那类问题。

### 4.3 自定义规则：禁止绕过 md-adapter

`02` 文档 §2.1 要求加一条 ESLint 规则，禁止渲染进程绕过 `packages/md-adapter` 直接操作 Markdown / ProseMirror。用 ESLint 内置的 `no-restricted-imports` 就能做，**不需要 typescript-eslint 的类型信息**（这是退路也能保住它的原因）：

```js
// eslint.config.mjs（片段）
{
  files: ['apps/desktop/src/renderer/**/*.{ts,tsx}'],
  ignores: ['apps/desktop/src/renderer/src/lib/editor-extensions.ts'],
  rules: {
    'no-restricted-imports': ['error', {
      paths: [
        { name: 'prosemirror-model', message: '正文读写必须经过 @inkstone/md-adapter，不要直接操作 ProseMirror。' },
        { name: '@tiptap/pm/model',  message: '同上。' },
      ],
      patterns: [
        { group: ['**/md-adapter/src/*'], message: '从包名 @inkstone/md-adapter 导入，不要深入源码路径。' },
      ],
    }],
  },
},
```

`editor-extensions.ts` 是唯一豁免点（它必须 `import { Heading } from '@tiptap/extension-heading'` 之类，但那些是**扩展**不是 schema 操作，其实不触发本条；保留豁免是为了避免将来加扩展时误报）。

### 4.4 flat config 结构

`eslint.config.mjs` 放仓库根：

```
ignores: node_modules / out / dist / .venv / **/*.d.ts / pnpm-lock.yaml
js.configs.recommended            → 全局
tseslint.configs.recommendedTypeChecked（若可用）→ apps/**、packages/**
react-hooks 插件                    → renderer/**
no-restricted-imports              → renderer/**（§4.3）
eslint-config-prettier             → 放最后（关掉所有与格式冲突的规则）
```

规则分级原则：

| 级别 | 用什么 | 例子 |
|---|---|---|
| `error` | 能导致数据丢失或静默错误的 | `no-floating-promises`、`no-restricted-imports` |
| `warn` | 风格与可读性 | `@typescript-eslint/no-unused-vars`（用 `^_` 前缀豁免） |
| 关掉 | 与 Prettier 冲突的、在 TS 下冗余的 | `no-undef`（TS 已知）、所有缩进/引号类 |

**先全部按 `warn` 跑一遍看数量**，再逐条升 `error` —— 一次性开满会淹没在几百条告警里，然后就会有人加 `eslint-disable` 了事。

## 5. Prettier 设计

| 项 | 值 | 理由 |
|---|---|---|
| `printWidth` | **100** | 与 `ruff` 的 `line-length = 100` 对齐。两侧行宽不一致会造成"改 Python 时按 100、改 TS 时按 120"的认知撕裂 |
| `singleQuote` | `true` | 现有代码就是这个风格 |
| `semi` | `true` | 同上 |
| `trailingComma` | `all` | 同上 |
| `endOfLine` | **`lf`** | 与 `.gitattributes` 的 `* text=auto eol=lf` 一致。设成 `auto` 会在 Windows 上生成 CRLF，进而破坏 md 适配层的字节级往返断言（`03` 文档的项目前提之一） |
| 忽略 | `pnpm-lock.yaml`、`*.md`（文档里有人工排版）、`out/`、`dist/` | 格式化 Markdown 会把精心排的表格与换行打散 |

分工：**格式一律交给 Prettier，ESLint 不碰格式**（`eslint-config-prettier` 负责关掉冲突规则）。

## 6. 脚本与 CI

### 6.1 脚本

```jsonc
// 根 package.json
"lint":        "eslint .",
"lint:fix":    "eslint . --fix",
"format":      "prettier --write .",
"format:check": "prettier --check .",
"verify":      "pnpm lint && pnpm typecheck && pnpm sidecar:test && pnpm shared:test && pnpm md-adapter:test && pnpm --filter @inkstone/desktop test"
```

`verify` 的改动：**补上 desktop 测试**（原来漏了 23 项），并在最前面加 `lint`。这样"一条命令验证全部"这句话才成立（README 里就是这么写的）。

### 6.2 CI（`.github/workflows/ci.yml`）

```yaml
name: CI
on: [push, pull_request]

jobs:
  node:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm lint
      - run: pnpm typecheck
      - run: pnpm shared:test
      - run: pnpm md-adapter:test
      - run: pnpm --filter @inkstone/desktop test

  python:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: services/sidecar } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.12', cache: pip }
      - run: python -m venv .venv
      - run: .venv/bin/python -m pip install -e ".[dev]"
      - run: .venv/bin/python -m ruff check src tests
      - run: .venv/bin/python -m mypy src
      - run: .venv/bin/python -m pytest
```

**几个必须注意的点**：

| 点 | 说明 |
|---|---|
| Python 用 **3.12** 而非 3.13 | `requires-python = ">=3.12"`，CI 取下限更能暴露兼容问题。本地 3.13 与 CI 3.12 都要过 |
| `pytest` 在 Linux 上跑 | `test_handshake.py` 会真的 spawn 进程、`taskkill` 相关分支在 Linux 上不走。**先跑一次看结果**，若有 Linux 特定失败，就在 CI 里 `-k "not handshake"` 并注明原因（本地覆盖） |
| 不用 `--frozen-lockfile` 装 sidecar | sidecar 不用 pnpm，用 pip |
| 缓存 | pnpm 与 pip 都开缓存，否则每次都重装 Electron（体积大） |
| **不跑 `pnpm dev` / 不装 Electron 二进制** | CI 只做静态检查与测试。`pnpm install` 会因为 `electron` 的 postinstall 下载二进制 —— 若太慢，加 `ELECTRON_SKIP_BINARY_DOWNLOAD=1` 环境变量（测试不需要 Electron 运行时） |

最后一条是实际会遇到的：Electron 的 postinstall 在 CI 上经常是耗时大头，而我们的测试（vitest）不依赖 Electron 运行时。

## 7. 异常与边界

| 场景 | 处理 |
|---|---|
| `typescript-eslint` 在 TS 7 下报内部错误 | 走 §4.2 的退路，**不要降级 TypeScript**（TS 7 是项目锁定版本，降级会牵动 electron-vite 与 vite 8） |
| `pnpm lint` 一次报几百条 | 先只对**改动过的文件**跑（`eslint --quiet`），把存量问题分批清理；CI 上先用 `continue-on-error` 跑一周，稳定后再转成阻断 |
| Windows 本地 lint 与 Linux CI 结果不一致 | 路径大小写、行尾（`.gitattributes` 已锁 LF）。若仍不一致，以 CI 为准 |
| mypy 与 ruff 的 line-length 都要 100 | 已有配置不动；Prettier 的 `printWidth` 对齐到 100 |
| CI 时长过长 | 两条 job 并行；Node job 跳过 Electron 二进制；不需要 `pnpm build`（typecheck 已覆盖编译错误） |

## 9. 风险

| 风险 | 对策 |
|---|---|
| `typescript-eslint` 与 TS 7 不兼容（§4.1 冲突 2） | 已给出退路，且退路能保住最关键的自定义规则（§4.3 不依赖类型信息）。**不牺牲 TypeScript 版本** |
| lint 规则一次性开太严，导致大量 `eslint-disable` | 先 warn 后 error，分批升级（§4.4） |
| CI 在 Linux 上跑不过握手测试 | §6.2 已预案；CI 与本地各有侧重，不追求"完全同一套" |
| `pnpm install` 在本机触发已知的 `os error 5/2` | 加依赖时若报错，按既有处置清理 `node_modules` 后重装（本机 `node_modules` 是 hoisted 布局，`.pnpm` 为空目录） |
| 装 lint 工具会改动 `package.json` 与 `node_modules` | **本步骤是唯一会大改依赖树的一步**；建议单独一个提交，便于回退 |

## 11. 实现偏差与补充（v0.2）

设计文档与代码冲突时，**以本节为准**。

### 11.1 §4.2 第二步的那条 `peerDependencyRules` **不仅是无效的，而且是错的**

v0.1 §4.2 让人在根 `package.json` 里加：

```json
"pnpm": { "peerDependencyRules": { "allowedVersions": { "typescript-eslint>typescript": "7" } } }
```

实测有两个问题，第二个更严重：

1. **位置无效**。pnpm 12 起只读 `pnpm-workspace.yaml`，`package.json` 的 `pnpm` 字段被忽略 —— 这条写下去连警告都没有，纯静默。
2. **规则本身反了**。它会把根 `node_modules/typescript` 拽到 7.x，而 typescript-eslint 8.70 在 TS 7 下**启动即 exit 2**（`typescript-eslint does not support TS 7.0.`）。也就是说"为了让它能跑"而加的豁免，恰恰会让它彻底不能跑。

最终做法是**一个字都不写**：

| 位置 | 版本 | 谁在用 |
|---|---|---|
| 根 `node_modules/typescript` | `~6.0.3` | 只给 typescript-eslint / `eslint.config.mjs` |
| `apps/desktop`、`packages/shared`、`packages/md-adapter` 各自那份 | `7.0.2` | 给各自 `pnpm typecheck` 的 `tsc` |

根 TS 6.0.3 本就落在 typescript-eslint 声明的 peer 区间 `>=4.8.4 <6.1.0` 内，所以**根本不需要豁免** —— §4.2 那句话的前提（"peer 上限是 6.1，而项目用 7"）在"把 lint 侧的 TS 与编译侧的 TS 分开"之后就不成立了。

项目的编译版本**没有降级**：三个包的 `pnpm typecheck` 走各自的 `node_modules/.bin/tsc`，解析到的是自己那份 7.0.2（已实测）。

> 记一笔好的一面：这个冲突是**响的** —— exit 2、文案明确，不是静默降级。本步骤踩到的坑大多是静默的（见 §11.3、§11.4），只有它一出来就喊。

### 11.2 `projectService: true` → 显式 `project: [...]`

§4.4 没规定用哪种项目发现方式。先按 typescript-eslint 推荐的 `projectService: true` 写，一次报 **12 条 fatal**：

```
Parsing error: .../apps/desktop/test/app-proxy.test.ts was not found by the project service
```

看着像代码坏了，其实是配置没被找到。原因：项目服务**只按文件名**向上找 `tsconfig.json`，而本仓库把配置拆成了 node / web 两份 —— `test/**` 只写在 `tsconfig.web.json`，`vitest.config.mts` 只写在 `tsconfig.node.json`，往上只找到 `apps/desktop/tsconfig.json`（它不含 `test/**`）。

改成显式列出 4 个 tsconfig，ESLint 依次匹配、取第一个包含该文件的。**代价**：以后新增包要记得往这个数组里补一行。

### 11.3 `tests/__init__.py` —— mypy overrides 生效的前提（静默失效，最坑的一条）

§3.4 写的 `[[tool.mypy.overrides]] module = "tests.*"` 在 `tests/` **不是包**的时候完全不生效：

- mypy 眼里的模块名是顶层的 `test_recent`、`test_atomic`……，不匹配 `tests.*`；
- 而 mypy 的 module 模式只允许整段 `*` 或 `.*`，**写不出 `test_*` 这种半通配**。

症状极具迷惑性：配置文件怎么看都对，错误却一条不减（实测 72 条）。处置是加一个空的 `services/sidecar/tests/__init__.py`。

最终落地的 override 键（比 §3.4 多三条，都是 pytest 惯用法带来的噪声）：

```toml
[[tool.mypy.overrides]]
module = "tests.*"
disallow_untyped_defs = false      # fixture 常常不标注
disallow_incomplete_defs = false   # fixture 常只标一部分参数
disallow_any_generics = false      # 测试里到处是裸 dict（构造请求体 / 断言响应）
warn_return_any = false            # response.json() 就是 Any，必然回流
disallow_any_expr = false
```

strict 的其余部分保留 —— 真问题（类型不兼容、属性不存在）仍然报。

### 11.4 pytest 的临时目录：钉 temproot **并且**给唯一 basetemp

`scripts/run-sidecar-tests.mjs` 做两件事：把 pytest 的临时根钉到工作区内的 `REPO_ROOT/.pytmp`，
并在调用方**未显式传 `--basetemp`** 时自动追加一个**本轮唯一**的 basetemp。

两个坑是独立的，只做第一件不够：

| # | 现象 | 成因 | 处置 |
|---|---|---|---|
| 1 | **测试全绿但 exit 1** | 默认临时根在系统 temp，pytest 收尾批量删上一轮目录，撞上本机沙箱的批量删除保护 | temproot 钉进 `.pytmp/` |
| 2 | **全部用例 `ERROR at setup`**（2026-09-23 复现） | 不给 `--basetemp` 时 pytest 走 `make_numbered_dir_with_cleanup(keep=3)`，每次启动删旧 `pytest-N` 会话目录；旧目录在同一父目录下持续累积，>50 文件时这一步被拦下，而它发生在**会话开始阶段** → `tmp_path` 在 setup 就 `SystemExit(1)` | 显式给每轮唯一的 `--basetemp` |

第 2 条实测报文：`{"count":326,…,"targets":[".pytmp\\pytest-of-40268\\pytest-current"]}`。
读数的误导性在于「全量 ERROR」看起来像代码坏了，实际收集数与基线一致、调用栈全落在删除拦截器上。

`.pytmp/` 已加入 `.gitignore`（含累积的 `bt-*`）。

⚠️ 另注：`pnpm -C <root> <script> -- <arg>` **会把 `--` 原样透传**给子进程（`node …mjs "--" "--basetemp=…"`），
下游若把 `--` 当"选项结束"符号，参数会被当成**文件路径**。要转发参数就绕开 pnpm，直接
`& "<node.exe>" scripts/run-sidecar-tests.mjs <arg>`。

### 11.5 `recent.py` 的 `list` 方法改名（§3.3 #1 的落地）

`StorageRecent.list()` → `list_entries()`，3 处调用点同步改。

成因如 §3.3 所料：方法名遮蔽了内置 `list`，于是**同一个类里**的注解 `list[dict[str, Any]]` 被解析成那个方法而不是内置类型。

### 11.6 前端四处真问题的修法

| 位置 | 规则 | 修法 |
|---|---|---|
| `TipTapEditor.tsx` | `no-unsafe-argument` ×2 | `PMNode.toJSON()` 在 `prosemirror-model` 的声明里返回 `any`，直接喂 `setContent` 触发。新增 `toTipTapContent(doc: { toJSON(): unknown })` 收敛成 `JSONContent`。参数用**结构化类型**而非 `import type { Node } from 'prosemirror-model'` —— 后者正是 `no-restricted-imports` 要拦的导入 |
| `WorkShell.tsx` | `no-misused-promises` ×3 | 侧栏 props 是 `() => void`，而 `switchTo` / `createChapter` / `refresh` 返回 `Promise<void>`。用三个 `useCallback` 包成 `void`。**没有内联箭头**：`switchTo` 必须保持稳定引用，否则侧栏每一项都会重渲染 |
| `chapter-list.ts` | `no-unnecessary-type-assertion` | `firstChapter` 的 `sorted[0]!` 去掉 `!` —— `noUncheckedIndexedAccess` 没开，索引访问本来就不是 `\| undefined` |
| `errors.ts` | `no-redundant-type-constituents` | `code: ErrorCode \| string` → `string` |
| `conflict-actions.test.ts` | `no-unnecessary-type-assertion` ×2 | `writes[0]!` / `creates[0]!` 去掉 `!` |

`errors.ts` 那条值得单独说：`ErrorCode` 是**字面量联合**，`ErrorCode | string` 里的 `string` 会把它整个吸收，类型系统直接化简成 `string` —— 既没换来收窄，又让人误以为这里做过校验。真实约束是运行时的（sidecar 是另一个进程、另一种语言，可能先于前端引入新码），所以诚实的写法就是 `string`，已知码由 `ErrorCode` 常量提供。

### 11.7 `react-hooks/set-state-in-effect` 降级为 `warn`（5 处）

规则建议"不要在 effect 里同步 setState"，理由是性能（多跑一轮渲染）。本仓库这 5 处都是**"外部输入变了就把内部状态复位"**：

- `App.tsx`：客户端重建（sidecar 重启）→ 丢弃上一次的探活结论
- `use-api-client.ts`：sidecar 非 HEALTHY → 丢掉 client
- `use-chapter-switch.ts`：换作品 / 换 workId → 清 notice、复位 switching
- `WorkShell.tsx`：冲突消失 → 关掉对话框
- `use-work-entry.ts`：reload 时清错误

按规则建议改成 key 重挂会**连组件实例与滚动位置一起丢掉**，代价比多一轮渲染大。所以降成 `warn`：继续可见，但不拦 CI。

### 11.8 测试文件关闭 `require-await`（20 处）

被拦下的全是**替身**：为了满足 `flush: () => Promise<boolean>`、`readChapter: () => Promise<ChapterContent>` 这类异步契约，最自然的写法就是 `async () => {…}`；另一种 `() => Promise.resolve(…)` 只是把噪音从规则挪进代码。

**覆盖面没有损失**：真正抓"忘了 `await`"的是 `no-floating-promises` 与 `await-thenable`，这两条在测试文件里**照常是 error** —— §12 #6 就是实测证据。

### 11.9 `verify` 增加两项（§6.1 原定义之外）

| 增加 | 理由 |
|---|---|
| `sidecar:lint`（ruff + mypy） | 不加的话，"一条命令验证全部"里不含 Python 静态检查 |
| `format:check` | 验收 §8 #2 要求它通过，但 §6.1 的 `verify` 与 §6.2 的 CI **都没有它** —— 格式没有任何强制点，装上第一天就会漂。成本约 1.5s |

CI 的 node job 同步加了 `format:check`。

### 11.10 CI 的 pnpm 版本钉在工作流里，不动 `packageManager`

§6.2 用了 `pnpm/action-setup@v4` 但没写版本。最终写在 `with.version: 12.4.2`。

**没有**往 `package.json` 加 `packageManager` 字段：那会让本机的 corepack 也按它校验版本，属于**会改变开发机行为**的副作用（本机的 pnpm 正是 corepack 提供的）。为了 CI 的可复现性去动开发机的工具链，不划算。

另外几处按 §6.2 的提示也落地了：`ELECTRON_SKIP_BINARY_DOWNLOAD=1` 设在 job 级 `env`；python job 的 `cache: pip` 显式给了 `cache-dependency-path`（不给的话 setup-python 在仓库根找不到依赖文件，只会打个 warning 然后不缓存）。

### 11.11 其它落地细节

- `.gitignore` 增加 `.pytmp/`（§11.4）与 `.logs/`（本机 PowerShell 不回传 stdout，命令输出统一重定向到仓库内再读回）。
- 删除 `tmp-clean.cjs` —— 早前清理 `node_modules` 留下的一次性脚本，不该进仓库。
- 全仓**首次** Prettier 一次性格式化了 24 个文件（`global.css`、`md-schema.ts`、若干测试等）。这是一次性成本，之后 `format:check` 会挡住增量漂移。
- `mypy` 与 `ruff` 的检查范围是 **`src tests`**（§3.5 要求测试也过），不是 `src`。CI 用同一条命令，避免"本地过、CI 挂在测试文件的标注上"。
- `eslint.config.mjs` 的 `ignores` 新增 `.pytmp/**`、`**/*.tsbuildinfo`。

### 12.1 #8 的两个已知待观察点

1. **`test_handshake.py` 在 Linux 上**：它会真的 spawn 子进程，而 Windows 特有的 `taskkill /T /F` 分支在 Linux 不走。CI 里目前**全量**跑 pytest；若首次 push 后这条失败，按 §7 的预案加 `-k "not handshake"` 并在本节写明原因（本地覆盖）。
